# 11장. 시제와 문장·제약의 연결

> 이 장에서 배우는 것
> - 문장과 사건의 시각에 미지값을 쓰는 법
> - "종료는 시작보다 앞설 수 없다"가 제약이 되는 원리
> - 이름 붙은 문장의 역할을 식에서 읽는 법
> - Reichenbach의 시제 모형과, 동사 어미가 시간 정보가 되는 원리
> - 같은 내용을 `사건`과 문장으로 쓰면 같은 판정이 나오는지

이 장의 기능은 RelSpec 0.5에서 들어왔습니다. 6장(사건), 7장(미지값), 8장(문장)을 하나로 엮는 장입니다.

## 11.1 문장 속의 미지값

8장의 문장에는 정의된 시각만 쓸 수 있었습니다. 0.5부터는 미지값도 쓸 수 있습니다.

```kpl
기준 실험시계: 시간축
대상 유빈
대상 버튼
행위 누르다: 주체, 대상, 시작
미지 반응: 시각 = 실험시계 @ ?

유빈이 반응에 버튼을 눌렀다
```

`사건` 선언도 마찬가지입니다. 0.3~0.4에서는 사건 역할에 미지값을 쓰면 `K406`이었지만, 0.5부터는 허용됩니다.

```kpl
기준 시계: 시간축
미지 가: 시각 = 시계 @ ?
사건 일: 시작 = 가, 종료 = 가 + 200 밀리초
검사 길이 = 일.소요 == 200 밀리초
```

`일.소요`는 (가 + 200) − 가 = 200밀리초로, 가를 몰라도 정확히 계산됩니다. 미지값은 식 안에서 **기호처럼** 다뤄지기 때문입니다. 내부적으로 값은 "상수 + Σ(계수 × 미지값)" 꼴로 저장되고, 빼기를 하면 미지값 부분이 서로 지워집니다. 중간 표현(12장)에도 종료의 값이 `가 + 200`처럼 기록됩니다.

## 11.2 시간 순서가 제약이 된다

6장에서 "종료는 시작보다 앞설 수 없다"를 배웠습니다. 값이 확정되어 있으면 바로 비교하면 됩니다. 그런데 시작이나 종료가 미지값이면 어떨까요?

RelSpec은 이 규칙을 **제약**으로 바꿔 7장의 해 집합에 더합니다. "시작 ≤ 종료"는 "시작 − 종료 ≤ 0"이라는 차이 제약이므로 STN의 간선 하나가 됩니다.

| 상황 | 동작 |
| --- | --- |
| 시작과 종료가 모두 확정 | 바로 비교. 어기면 `K402` |
| 미지값이 있음 | 차이 제약으로 더함. 앞선 조건과 모순이면 `K402` |

이것은 두 가지를 뜻합니다.

**1. 사건 선언이 정보를 더합니다.** 다음 예에서 `정지`에 직접 건 조건은 없지만, 사건 `굴림`의 종료라는 사실 때문에 "정지 ≥ 출발"이 성립합니다.

```kpl
기준 시계: 시간축
미지 출발: 시각 = 시계 @ ?
미지 정지: 시각 = 시계 @ ?
사건 굴림: 시작 = 출발, 종료 = 정지
조건 시작범위 = 출발 >= 시계 @ 1 초 그리고 출발 <= 시계 @ 2 초
조건 길이 = 굴림.소요 <= 3 초
목표 시작전끝남 = 굴림.종료 < 굴림.시작
```

```text
미지 '출발': 1000 밀리초 ~ 2000 밀리초 (시계 기준)
미지 '정지': 1000 밀리초 ~ 5000 밀리초 (시계 기준)
목표 '시작전끝남': 불가능
```

**2. 모순은 어느 쪽에서든 잡힙니다.** 조건이 먼저 "가가 나보다 뒤"라고 정했다면, 가에 시작해 나에 끝나는 사건은 있을 수 없습니다.

```kpl 오류=K402
기준 시계: 시간축
미지 가: 시각 = 시계 @ ?
미지 나: 시각 = 시계 @ ?
조건 순서 = 가 - 나 >= 1 초
사건 일: 시작 = 가, 종료 = 나
```

```text
예제.kpl(5,4): error K402: 사건 '일'의 종료(나)가 시작(가)보다 앞섭니다. 앞선 조건에 따르면 항상 그렇습니다.
```

순서를 바꾸어 사건을 먼저 쓰면, 뒤에 오는 조건이 모순으로 보고됩니다. 어느 쪽이 "틀렸는지"는 컴파일러가 알 수 없으므로, 파일에서 나중에 나온 쪽을 보고합니다.

```kpl 오류=K404
기준 시계: 시간축
미지 가: 시각 = 시계 @ ?
미지 나: 시각 = 시계 @ ?
사건 일: 시작 = 가, 종료 = 나
조건 순서 = 가 - 나 >= 1 초
```

```text
예제.kpl(5,4): error K404: 조건 '순서'이 앞선 조건·관측과 모순됩니다. 앞선 조건: '나 - 가' 최소 0 밀리초. 이 조건: '나 - 가' 최대 -1000 밀리초.
```

## 11.3 이름 붙은 문장은 사건이기도 하다

10장에서 `이름: 문장`의 이름은 문장의 정도였습니다. 0.5부터는 같은 이름으로 문장의 역할도 읽을 수 있습니다. `이름` 자체는 정도이고, `이름.역할`은 사건의 역할입니다.

```kpl
기준 시계: 시간축
대상 공
행위 구르다: 주체
정의 가: 시각 = 시계 @ 1 초
정의 나: 시각 = 시계 @ 4 초

굴림: 공이 가부터 나까지 60% 굴렀다
검사 비율 = 굴림 == 60%
검사 길이 = 굴림.소요 == 3 초 그리고 굴림.주체 == 공
```

6장의 사건과 달리, 문장은 종료를 적지 않았을 때 종료를 시작으로 채우지 않습니다. 문장에는 시제가 있어서(11.5), "끝나지 않은 사건"을 말할 수 있어야 하기 때문입니다. 그래서 종료가 없는 문장의 `소요`는 읽을 수 없습니다(`K314`).

## 11.4 위치는 뒤로 움직일 수 있다

시간과 달리 위치에는 순서 제약이 없습니다. 공은 5미터 지점에서 1미터 지점으로 굴러갈 수 있습니다.

```kpl
기준 복도: 위치축
대상 공
행위 구르다: 주체
정의 가: 위치 = 복도 @ 5 미터
정의 나: 위치 = 복도 @ 1 미터
굴림: 공이 가부터 나까지 굴렀다
검사 뒤로 = 굴림.이동 == -4 미터
```

`이동`이 음수인 것은 축의 반대 방향으로 움직였다는 뜻입니다. 0.4에서는 이 문장을 `K402`로 잘못 거절했고, 0.5에서 바로잡았습니다.

## 11.5 이론: Reichenbach의 시제 모형

"유빈이 버튼을 눌렀다"와 "유빈이 버튼을 누르겠다"는 같은 사건을 말하지만, 그 사건이 **언제인지에 대해** 다른 정보를 줍니다. 앞 문장은 "말하는 지금보다 앞에", 뒷 문장은 "지금보다 뒤에"라는 정보입니다.

철학자이자 물리학자인 Hans Reichenbach는 1947년 *Elements of Symbolic Logic*에서 시제를 세 시각의 순서 관계로 분석했습니다.

| 기호 | 이름 | 뜻 |
| --- | --- | --- |
| S | 발화시 (speech time) | 말하는 순간 |
| E | 사건시 (event time) | 사건이 일어난 때 |
| R | 기준시 (reference time) | 말하는 사람이 관점을 둔 때 |

단순한 시제에서는 R과 E가 같고, 시제는 E와 S의 관계로 정해집니다.

| 시제 | 관계 | 예 |
| --- | --- | --- |
| 과거 | E < S | 눌렀다 |
| 현재 | E = S (S가 E 안에 있음) | 누른다 |
| 미래 | S < E | 누르겠다 |

R이 E와 다른 경우는 "그때는 이미 눌렀었다"(대과거: E < R < S) 같은 복합 시제에서 나타납니다. RelSpec은 현재 단순한 시제만 다룹니다.

이 분석의 요점은 **시제가 문법 표지이면서 동시에 시간에 대한 주장**이라는 것입니다. 그리고 시간에 대한 주장이라면, 7장의 제약으로 바꿀 수 있습니다.

## 11.6 시제를 읽는 법

컴파일러는 동사의 활용형에서 시제를 읽습니다. 한국어의 시제는 어간과 어미 사이에 들어가는 **선어말어미**로 표시됩니다.

| 시제 | 표지 | 컴파일러가 보는 것 | 예 |
| --- | --- | --- | --- |
| 과거 | -았/었/였- | 어간 뒤 음절에 받침 ㅆ | 했다, 졌다, 왔다, 먹었다 |
| 미래 | -겠- | '겠' 음절 | 하겠다, 먹겠다 |
| 현재 | -ㄴ다/-는다 | '-는다'로 끝나거나 '다' 앞 음절에 받침 ㄴ | 한다, 먹는다, 구른다 |
| 없음 | (기본형) | 선언한 기본형과 같음 | 하다, 먹다 |

과거 표지 -았/었/였-은 앞 음절과 합쳐지더라도 **ㅆ 받침**을 남깁니다(하+였 → 했, 지+었 → 졌). 그래서 받침 ㅆ으로 과거를 알아볼 수 있습니다. 이때 '있다'처럼 어간 자체에 ㅆ이 있는 동사를 과거로 착각하지 않도록, 바뀌지 않는 어간 앞부분은 건너뛰고 봅니다. 기본형 '있다'는 시제가 없고, '있었다'는 과거입니다.

```kpl
대상 유빈
행위 하다: 주체
행위 먹다: 주체
행위 있다: 주체
유빈이 했다
유빈이 한다
유빈이 하겠다
유빈이 하다
유빈이 먹는다
유빈이 있다
유빈이 있었다
```

이 파일을 `컴파일`하면 문장마다 `tense`에 `과거`, `현재`, `미래`가 기록되고, 기본형 문장에는 기록되지 않습니다.

## 11.7 지금과 시제 제약

`지금`이라는 이름의 `시각`을 정의하면, 시제가 있는 문장마다 다음 관계가 제약으로 더해집니다. `지금`은 예약어가 아니라 평범한 이름이지만, 시각으로 정의되면 이런 특별한 뜻을 가집니다.

| 시제 | 더하는 관계 |
| --- | --- |
| 과거 | 종료(없으면 시작) ≤ 지금 |
| 현재 | 시작 ≤ 지금, 그리고 종료가 있으면 지금 ≤ 종료 |
| 미래 | 지금 < 시작 |

`지금`이 정의되지 않았거나, 문장에 시각 역할이 없으면 시제는 기록만 되고 제약은 더하지 않습니다.

### 예제: 시제가 범위를 좁힌다

```kpl
기준 실험시계: 시간축
대상 유빈
대상 버튼
대상 화면
행위 켜지다: 주체, 시작
행위 누르다: 주체, 대상, 시작

정의 지금: 시각 = 실험시계 @ 3 초
정의 점등: 시각 = 실험시계 @ 1000 밀리초
미지 반응: 시각 = 실험시계 @ ?

자극: 화면이 점등에 켜졌다
눌림: 유빈이 반응에 버튼을 눌렀다

조건 자극뒤 = 눌림.시작 >= 자극.시작
조건 지연상한 = 눌림.시작 - 자극.시작 <= 2500 밀리초
목표 마감 = 눌림.시작 <= 실험시계 @ 2500 밀리초
목표 여유 = 눌림.시작 <= 실험시계 @ 3 초
```

```text
미지 '반응': 1000 밀리초 ~ 3000 밀리초 (실험시계 기준)
목표 '마감': 가능 (보장 여부를 확정하려면 관측 필요: 반응)
목표 '여유': 보장
```

조건만 보면 반응은 1000~3500밀리초입니다(자극 후 2500밀리초 이내). 그런데 "눌렀다"가 과거이므로 반응 ≤ 지금(3000밀리초)이 더해져 범위가 1000~3000밀리초로 좁혀졌습니다. 그 덕분에 `여유` 목표가 보장이 되었습니다. **동사 어미 하나가 판정을 바꾼 것**입니다.

같은 파일에서 "눌렀다"를 "누르겠다"로 바꾸면 반응 > 지금이 더해져 범위가 3001~3500밀리초가 되고, `여유`는 불가능이 됩니다. "누르다"(기본형)로 바꾸면 시제 제약이 없어 1000~3500밀리초입니다.

### 시제 모순: K530

시제와 시각이 맞지 않으면 `K530`입니다. 1초에 켜진 화면을 미래 시제로 쓸 수는 없습니다.

```kpl 오류=K530
기준 실험시계: 시간축
대상 화면
행위 켜지다: 주체, 시작
정의 지금: 시각 = 실험시계 @ 3 초
정의 점등: 시각 = 실험시계 @ 1000 밀리초
화면이 점등에 켜지겠다
```

```text
예제.kpl(6,9): error K530: '켜지겠다'는 미래 시제이므로 사건이 지금보다 뒤에 시작하는 것이어야 하지만 그렇지 않습니다.
```

현재 시제는 "지금이 사건 안에 있다"는 뜻이므로, 이미 끝난 사건을 현재형으로 쓰면 오류입니다.

```kpl 오류=K530
기준 시계: 시간축
대상 공
행위 구르다: 주체
정의 지금: 시각 = 시계 @ 5 초
정의 가: 시각 = 시계 @ 1 초
정의 나: 시각 = 시계 @ 3 초
공이 가부터 나까지 구른다
```

```text
예제.kpl(7,12): error K530: '구른다'는 현재 시제이므로 사건이 지금 이후에 끝나는 것이어야 하지만 그렇지 않습니다.
```

`지금`과 사건 시각은 같은 기준에 있어야 합니다. 다르면 `K306`입니다.

## 11.8 두 표기, 같은 판정

8장에서 문장과 `사건` 선언은 같은 내부 모델로 바뀐다고 했습니다. 0.5에서는 이것을 시험으로 확인합니다. 다음 두 명세는 표기만 다릅니다.

```kpl
기준 시계: 시간축
대상 공
행위 구르다: 주체, 시작
미지 출발: 시각 = 시계 @ ?
미지 정지: 시각 = 시계 @ ?
사건 굴림: 주체 = 공, 시작 = 출발, 종료 = 정지
조건 시작범위 = 굴림.시작 >= 시계 @ 1 초 그리고 굴림.시작 <= 시계 @ 2 초
조건 길이 = 굴림.소요 <= 3 초
목표 늦게끝남 = 굴림.종료 >= 시계 @ 4 초
목표 빨리끝남 = 굴림.종료 <= 시계 @ 5 초
```

```kpl
기준 시계: 시간축
대상 공
행위 구르다: 주체, 시작
미지 출발: 시각 = 시계 @ ?
미지 정지: 시각 = 시계 @ ?
굴림: 공이 출발부터 정지까지 굴렀다
조건 시작범위 = 굴림.시작 >= 시계 @ 1 초 그리고 굴림.시작 <= 시계 @ 2 초
조건 길이 = 굴림.소요 <= 3 초
목표 늦게끝남 = 굴림.종료 >= 시계 @ 4 초
목표 빨리끝남 = 굴림.종료 <= 시계 @ 5 초
```

두 파일 모두 `늦게끝남`은 가능, `빨리끝남`은 보장이고, `정지`의 범위는 1000~5000밀리초입니다. 저장소의 `tests/linking.rs`가 이 동등성을 확인합니다. 사용자는 상황에 맞는 표기를 고를 수 있고, 어느 쪽을 골라도 판정은 같습니다.

## 정리

- 문장과 사건의 시각·위치에 미지값을 쓸 수 있으며, 미지값은 식 안에서 기호처럼 계산됩니다.
- "종료 ≥ 시작"은 확정값이면 바로 확인하고, 미지값이면 STN 제약이 됩니다.
- 이름 붙은 문장은 정도이면서 사건입니다(`이름`, `이름.역할`).
- 시제는 발화시와 사건시의 관계입니다(Reichenbach). `지금`을 정의하면 시제가 제약이 됩니다.
- 같은 내용을 `사건`과 문장으로 쓰면 같은 판정이 나옵니다.

## 연습 문제

1. 지금이 10초이고 미지값 `도착`(시계 위의 시각)이 있습니다. "택배가 도착에 왔다"와 "택배가 도착에 오겠다"는 각각 도착의 범위에 어떤 제약을 더할까요?
2. 11.7의 예제에서 지금을 2초로 바꾸면 반응의 범위와 `여유` 목표의 판정은 어떻게 될까요?
3. 시작이 미지값 가인 사건에서 종료를 `가 - 100 밀리초`로 쓰면 어떤 일이 생길까요?

<details>
<summary>풀이</summary>

1. "왔다"(과거)는 도착 ≤ 10초, "오겠다"(미래)는 도착 > 10초, 즉 도착 ≥ 10001밀리초를 더합니다.
2. 반응 ≤ 2000밀리초가 더해져 범위는 1000~2000밀리초가 되고, `여유`(≤ 3초)는 여전히 보장입니다. `마감`(≤ 2.5초)도 보장이 됩니다.
3. 종료 − 시작 = −100밀리초로 확정되므로 미지값과 상관없이 종료가 시작보다 앞섭니다. 차이 제약 "가 − (가 − 100) ≤ 0", 즉 100 ≤ 0이 거짓이어서 `K402`입니다.

```kpl
기준 시계: 시간축
대상 택배
행위 오다: 주체, 시작
정의 지금: 시각 = 시계 @ 10 초
미지 도착: 시각 = 시계 @ ?
택배가 도착에 왔다
검사 과거 = 도착 <= 지금
```

```kpl 오류=K402
기준 시계: 시간축
미지 가: 시각 = 시계 @ ?
사건 일: 시작 = 가, 종료 = 가 - 100 밀리초
```
