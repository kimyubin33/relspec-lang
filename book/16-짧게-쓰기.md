# 16장. 짧게 쓰기

> 이 장에서 배우는 것
> - 여러 이름을 한 줄에 선언하는 법
> - 이름 없이 쓰는 검사·조건·목표
> - 타입을 적지 않는 정의와, 컴파일러가 타입을 정하는 방법
> - `단위`로 새 단위를 만드는 법과 `120만 원` 같은 수
> - 문장 뒤에 설명을 붙이는 법과, 긴 설명을 여러 줄로 나누는 법
> - 덜어낸 것과 덜어내지 않은 것

이 장의 기능은 RelSpec 0.9에서 들어왔고, 16.9의 딸린 줄은 0.11에서 들어왔습니다. 앞 장들에서 배운 문법은 모두 그대로 쓸 수 있습니다. 이 장은 같은 뜻을 더 적은 줄로 쓰는 방법을 다룹니다.

## 16.1 무엇이 번거로웠나

0.8까지의 문법으로 실제 조사 요청서를 써 보니, 내용을 적는 데 필요한 줄보다 형식을 맞추는 데 필요한 줄이 더 많았습니다.

| 번거로움 | 원인 |
| --- | --- |
| 문장 9줄을 쓰려고 `대상` 10줄과 `행위` 4줄을 먼저 씀 | 선언을 한 줄에 하나씩만 할 수 있었음 |
| `기관수범위`, `최저가격일치` 같은 이름을 14개 지어냄 | 검사·조건·목표마다 이름이 필수였음 |
| `정의 최저가격: 정수 = 1200000` | 값을 보면 알 수 있는 타입도 적어야 했고, '원'을 쓸 수 없었음 |
| 문장마다 "이렇게 … (참조 N)"을 쓰고 내용은 멀리 아래에 적음 | 설명을 문장 옆에 적을 방법이 없었음 |

이 번거로움은 규칙이 엄격해서 생긴 것이 아닙니다. 주체가 없는 문장을 거절하는 것은 엄격함이고, 이름을 14개 짓게 하는 것은 절차입니다. 0.9는 엄격함은 그대로 두고 절차만 덜어냈습니다. 한 줄에 뜻 하나를 적는다는 원칙도 그대로입니다.

## 16.2 여러 이름을 한 줄에

쉼표로 나누어 여러 이름을 선언합니다.

```kpl
대상 신청자, 강의실, 담당자
행위 예약하다, 승인하다 (승인했다): 주체, 대상

신청자가 강의실을 예약한다
담당자가 강의실을 승인했다
```

- `대상 가, 나, 다`는 `대상` 세 줄과 같습니다.
- `행위 가다, 오다: 역할들`에서 쉼표로 나눈 행위들은 `:` 뒤의 필수 역할을 함께 씁니다. 활용형을 적는 괄호는 행위마다 따로 붙입니다.
- 뒤에서 배울 `단위`와 `미지`도 같은 방식으로 여러 이름을 받습니다.

함께 선언해도 규칙은 행위마다 적용됩니다.

```kpl 오류=K504
대상 신청자, 강의실
행위 예약하다, 승인하다: 주체, 대상
강의실을 승인한다
```

```text
예제.kpl(3,6): error K504: 행위 '승인하다'에는 '주체' 역할이 필요합니다. 누가 했는지(주체)가 없습니다. '유빈이'처럼 이/가 조사로 밝히세요.
```

같은 이름을 두 번 적으면 한 줄 안에서도 `K301`입니다.

```kpl 오류=K301
대상 컵, 바닥, 컵
```

## 16.3 이름 없는 검사, 조건, 목표

`검사`, `조건`, `목표`는 이름과 `=`를 빼고 식만 적을 수 있습니다.

```kpl
정의 정원 = 40
정의 마감 = 2 초
정의 열림 = 참
정의 확신 = 80%
검사 정원 > 0
검사 마감 < 3 초

미지 참석자: 정수
조건 참석자 >= 1
조건 참석자 <= 정원
목표 참석자 <= 50
목표 참석자 > 10
목표 가득참 = 참석자 > 정원
```

```text
미지 '참석자': 1 ~ 40
목표 '참석자 <= 50': 보장
목표 '참석자 > 10': 가능 (보장 여부를 확정하려면 관측 필요: 참석자)
목표 '가득참': 불가능
```

이름이 없으면 결과에 식이 그대로 표시됩니다. 이름이 필요한 경우는 두 가지입니다. 식이 길어서 결과를 짧게 부르고 싶을 때, 그리고 중간 표현을 읽는 다른 도구가 고정된 이름으로 찾아야 할 때입니다.

**이름인지 식인지를 가르는 방법.** `조건 참석자 >= 1`과 `조건 하한 = 참석자 >= 1`은 둘 다 `조건` 뒤에 이름으로 시작합니다. 컴파일러는 그 이름의 **다음 토큰 하나**를 봅니다. `=`이면 이름 있는 꼴이고, 아니면 식의 시작입니다. 비교는 `==`로 쓰므로(4장) `=`와 헷갈리지 않습니다. 이렇게 토큰을 몇 개 미리 보고 문법의 갈래를 정하는 것을 **미리 보기**(lookahead)라고 합니다.

**이름 없는 줄은 이름을 만들지 않습니다.** 그래서 같은 식을 두 번 적어도 이름이 겹친다는 오류(`K301`)가 나지 않고, 식에서 그 줄을 가리킬 수도 없습니다.

```kpl
정의 켜짐 = 참
검사 켜짐
검사 켜짐
```

## 16.4 타입을 적지 않는 정의

`정의 이름 = 식`은 식의 타입을 그대로 따릅니다. 16.3의 예에서 `정원`은 정수, `마감`은 시간, `열림`은 논리, `확신`은 정도가 됩니다. 타입을 적으면 전과 같이 확인합니다.

```kpl 오류=K303
정의 마감: 정수 = 2 초
```

타입을 적는 것은 이제 "이 값은 반드시 이 타입이어야 한다"는 뜻을 밝히고 싶을 때의 선택입니다.

미지값은 값이 없으므로 타입을 생략할 수 없습니다. 대신 `= ?`를 생략합니다.

```kpl
미지 가, 나: 시간
조건 가 >= 1 초
조건 나 - 가 >= 2 초
```

시각과 위치는 어느 기준 위의 점인지가 타입의 일부입니다(5장). 기준은 추측할 수 없으므로 적어야 합니다.

```kpl 오류=K200
기준 시계: 시간축
미지 도착: 시각
```

```text
예제.kpl(2,8): error K200: '시각'은 기준 위의 점이므로 '= 기준 @ ?'로 적으세요.
```

## 16.5 이론: 타입 추론과 문법 설탕

### 타입 추론

타입을 다루는 방향은 둘입니다.

- **확인**(checking): 기대하는 타입이 먼저 있고, 식이 그 타입인지 봅니다. `정의 마감: 시간 = 2 초`에서 `시간`이 기대하는 타입입니다.
- **합성**(synthesis): 식에서 타입을 구해 냅니다. `2 초`는 수에 시간 단위가 붙었으므로 시간입니다.

RelSpec의 식은 언제나 합성이 됩니다. 리터럴은 모양으로 타입이 정해지고(`3`, `2 초`, `참`, `80%`), 이름은 선언에서, 연산은 4장과 5장의 표에서 타입이 정해집니다. 0.8까지도 컴파일러는 식의 타입을 합성한 다음 적어 둔 타입과 견주었습니다. 0.9는 견줄 타입이 없으면 합성한 타입을 그대로 쓰는 것뿐입니다. 이렇게 한 문장 안에서 끝나는 추론을 **지역 타입 추론**이라고 합니다.

함수가 있는 언어에서는 타입 추론이 훨씬 어렵습니다. 함수의 매개변수처럼 쓰임새를 보아야 타입이 정해지는 자리가 있어서, 타입에 대한 방정식을 세우고 푸는 과정이 필요합니다(Hindley–Milner 방식). RelSpec에는 그런 자리가 없으므로 그 장치가 필요하지 않습니다. 미지값에 타입을 꼭 적게 한 것도 같은 이유입니다. 미지값의 타입을 쓰임새에서 구하려면 방정식 풀이가 필요해지고, 오류가 났을 때 어느 줄이 잘못인지 가리키기도 어려워집니다.

### 문법 설탕

`대상 가, 나`는 새로운 뜻을 더하지 않습니다. `대상 가`와 `대상 나` 두 줄로 바꿔 쓸 수 있습니다. 이렇게 이미 있는 문법으로 바꿔 쓸 수 있는 편의 문법을 **문법 설탕**(syntactic sugar)이라고 합니다. 영국의 전산학자 Peter Landin이 1960년대에 붙인 이름입니다. 컴파일러가 설탕을 기본 문법으로 바꾸는 일을 **설탕 걷어내기**(desugaring)라고 합니다.

RelSpec 컴파일러는 구문 분석 단계에서 여러 이름 선언을 선언 여러 개로 풀어 놓습니다. 그 뒤의 단계는 0.8과 같은 것을 받으므로, 필수 역할 검사나 중복 이름 검사 같은 규칙이 새 문법에서도 빠짐없이 적용됩니다. 16.2에서 함께 선언한 행위에 `K504`가 그대로 나온 것이 그 결과입니다.

| 0.9의 문법 | 성격 |
| --- | --- |
| `대상 가, 나`, `행위 가다, 오다: …`, `미지 가, 나: …` | 문법 설탕: 여러 줄로 풀림 |
| `미지 가: 시간` | 문법 설탕: `미지 가: 시간 = ?` |
| `정의 가 = 식` | 타입 추론 |
| `조건 식` | 이름 공간을 쓰지 않는 새 꼴 |
| `단위 원` | 새 기능: 타입이 늘어남 |

## 16.6 단위를 선언하기

3장에서 본 단위는 시간(밀리초, 초)과 거리(밀리미터, 센티미터, 미터)뿐이었습니다. 금액이나 인원은 단위 없는 정수로 적어야 했고, 그러면 원과 명을 더해도 컴파일러가 알 수 없었습니다. `단위`는 새 단위를 만듭니다.

```kpl
단위 원, 명
정의 기본요금 = 3만 원
정의 정원 = 40 명
정의 두배 = 기본요금 * 2
검사 기본요금 < 10만 원
```

선언한 단위마다 새 타입이 하나 생깁니다. 같은 단위끼리는 더하고 빼고 비교할 수 있고, 정수를 곱할 수 있습니다. 단위가 다르면 섞을 수 없습니다.

```kpl 오류=K304
단위 원, 명
정의 기본요금 = 3만 원
정의 정원 = 40 명
정의 합계 = 기본요금 + 정원
```

```text
예제.kpl(4,14): error K304: '+' 연산에 사용할 수 없는 조합입니다. 왼쪽은 원, 오른쪽은 명입니다.
```

단위 없는 수와도 섞이지 않습니다. 0과 비교할 때도 `0 원`이라고 적습니다.

```kpl 오류=K304
단위 원
정의 기본요금 = 3만 원
검사 기본요금 > 0
```

```text
예제.kpl(3,9): error K304: '>' 연산에 사용할 수 없는 조합입니다. 왼쪽은 원, 오른쪽은 정수입니다.
```

선언하지 않은 낱말을 수 뒤에 적으면 `K315`입니다.

```kpl 오류=K315
정의 기본요금 = 3만 원
```

```text
예제.kpl(1,14): error K315: '원'은 단위가 아닙니다. 단위로 쓰려면 앞에서 '단위 원'으로 선언하세요. 이미 있는 단위는 밀리초, 초, 분, 시간, 일, 밀리미터, 센티미터, 미터, 킬로미터입니다.
```

단위는 미지값의 타입으로도 씁니다.

```kpl
단위 원
정의 기본요금 = 3만 원
정의 최대요금 = 1억 2000만원
정의 회의 = 30 분
정의 수업 = 2 시간
미지 요금: 원
미지 사용, 준비: 시간
조건 요금 >= 기본요금
조건 사용 >= 회의
조건 준비 - 사용 >= 10 분
목표 요금 <= 최대요금
목표 사용 <= 수업
```

```text
미지 '요금': 30000 원 ~ 상한 없음
미지 '사용': 1800000 밀리초 ~ 상한 없음
미지 '준비': 2400000 밀리초 ~ 상한 없음
목표 '요금 <= 최대요금': 가능 (보장 여부를 확정하려면 관측 필요: 요금)
목표 '사용 <= 수업': 가능 (보장 여부를 확정하려면 관측 필요: 사용)
```

### 큰 수 낱말

수 뒤에 `십`, `백`, `천`, `만`, `십만`, `백만`, `천만`, `억`, `십억`, `백억`, `천억`, `조`를 붙여 씁니다. `1억 2000만`처럼 이어 쓸 수 있고, 단위와 붙여 `3만원`이라고 써도 됩니다.

| 쓴 것 | 값 |
| --- | --- |
| `3만` | 30000 |
| `5천` | 5000 |
| `1억 2000만` | 120000000 |
| `3만 원`, `3만원` | 30000 원 |

`3만원`에서 컴파일러는 먼저 `만원` 전체가 선언한 단위인지 보고, 아니면 `만`과 `원`으로 나눕니다. 그래서 `만원`이라는 단위를 따로 선언하지 않는 한 `3만원`은 30000 원입니다.

### 더 긴 시간과 거리

`분`, `시간`, `일`은 시간의 단위이고 `킬로미터`는 거리의 단위입니다. 값은 3장의 단위와 같은 타입이며 기본 단위(밀리초, 밀리미터)로 저장됩니다.

| 단위 | 타입 | 기본 단위로 |
| --- | --- | --- |
| `분` | 시간 | 60000 밀리초 |
| `시간` | 시간 | 3600000 밀리초 |
| `일` | 시간 | 86400000 밀리초 |
| `킬로미터` | 거리 | 1000000 밀리미터 |

```kpl
정의 회의 = 30 분
정의 수업 = 2 시간
검사 수업 == 120 분
검사 회의 + 90 분 == 수업
```

이 낱말들은 수 바로 뒤에서만 단위로 읽으므로 예약어가 아닙니다. `일`이나 `분`을 이름으로 써도 됩니다. 같은 이름의 단위를 선언하면 선언한 쪽이 먼저입니다(`단위 분`을 선언하면 `3 분`은 시간이 아니라 분 단위의 양입니다).

결과에 범위가 `1800000 밀리초`처럼 기본 단위로 표시되는 것은 아직 고치지 못한 부분입니다.

## 16.7 이론: 단위는 타입이다

3장에서 Mars Climate Orbiter 이야기를 했습니다. 한쪽은 파운드 단위로, 다른 쪽은 뉴턴 단위로 같은 수를 읽어 탐사선을 잃은 사고입니다. 수만 주고받으면 단위는 사람의 기억에만 남습니다.

물리학에는 이를 막는 오래된 방법이 있습니다. **차원 분석**입니다. 길이와 시간은 서로 다른 **차원**이고, 차원이 다른 양은 더하거나 비교할 수 없다는 규칙입니다. 3 미터 + 2 초는 계산할 방법이 없는 것이 아니라 뜻이 없는 식입니다.

프로그래밍 언어는 이 규칙을 타입 검사로 옮길 수 있습니다. 양의 타입에 차원을 넣어 두면, 차원이 맞지 않는 식은 타입 오류가 됩니다. Andrew Kennedy가 1990년대에 이 방법을 체계화했고, 그의 설계가 F# 언어의 "측정 단위" 기능이 되었습니다.

RelSpec의 `단위`는 이 생각의 가장 단순한 형태입니다.

- **단위 하나가 차원 하나입니다.** `단위 원, 달러`를 선언하면 둘은 서로 다른 타입이며, 환율로 바꿔 주지 않습니다. 이름이 다르면 다른 타입으로 보는 이런 방식을 **이름에 의한 타입 구분**(nominal typing)이라고 합니다.
- **더하기, 빼기, 비교, 정수배만 됩니다.** 차원 분석에서는 차원끼리 곱하고 나눌 수 있습니다(거리 ÷ 시간 = 속도). RelSpec은 아직 그것을 지원하지 않습니다. `원 ÷ 명`으로 1인당 금액을 구하는 식은 쓸 수 없습니다.

기본 단위인 시간과 거리는 조금 다릅니다. `초`와 `분`은 같은 차원(시간)의 서로 다른 단위이며, 컴파일러가 배수를 알고 있어서 섞어 쓸 수 있습니다. `단위`로 선언한 단위에는 아직 이런 배수 관계를 줄 수 없습니다.

| | 기본 단위 (초, 분, 미터 …) | 선언한 단위 (원, 명 …) |
| --- | --- | --- |
| 차원 | 시간, 거리 두 가지 | 단위마다 하나 |
| 같은 차원의 다른 단위 | 있음 (초 ↔ 분) | 없음 |
| 미지값과 제약 | 가능 | 가능 |
| 문장에서의 쓰임 | 시각·위치로 역할을 맡음 | 아직 없음 |

### 왜 `만`인가

`1,200,000`은 세 자리씩 끊어 읽는 서양식 표기입니다. 한국어는 수를 네 자리씩 끊어 읽습니다(만, 억, 조). 그래서 `1200000`을 읽으려면 자리를 세어야 하고, `120만`은 바로 읽힙니다. 금액을 다루는 명세에서 자릿수를 잘못 세는 실수는 흔하고 결과가 큽니다. 큰 수 낱말은 읽는 방식과 쓰는 방식을 맞춘 것입니다.

## 16.8 문장 옆 설명

9장에서는 문장이 가리키는 내용을 지시어와 참조로 적었습니다.

```text
신청자가 강의실을 이렇게 예약한다 (참조 1)
참조 1: 수업 시작 2일 전까지 신청서를 낸다
```

0.9부터는 문장 뒤에 `:`를 쓰고 설명을 바로 적을 수 있습니다.

```kpl
대상 신청자, 강의실
행위 예약하다: 주체, 대상
신청자가 강의실을 예약한다: 수업 시작 2일 전까지 신청서를 낸다 (#은 주석이 아님)
```

- `:` 뒤부터 줄 끝까지가 설명입니다. 참조의 본문처럼 낱말로 나누지 않으며, `#`과 기호도 설명의 일부입니다.
- 이름 붙은 문장에도 붙입니다. `이름: 문장: 설명`에서 첫 `:`는 이름, 둘째 `:`는 설명입니다.
- 조건문(14장)에도 붙입니다.
- 설명은 중간 표현에서 문장의 `note` 항목이 됩니다.

설명은 문장의 역할이 아닙니다. 그래서 설명에 무엇을 적든 문장의 규칙은 그대로 적용됩니다.

```kpl 오류=K504
대상 신청자, 강의실
행위 예약하다: 주체, 대상
강의실을 예약한다: 신청자가 이틀 전까지 신청서를 낸다
```

```text
예제.kpl(3,6): error K504: 행위 '예약하다'에는 '주체' 역할이 필요합니다. 누가 했는지(주체)가 없습니다. '유빈이'처럼 이/가 조사로 밝히세요.
```

설명 안에 "신청자가"가 있지만 문장에는 주체가 없습니다. 컴파일러가 보장하는 것은 `:` 앞의 문장까지입니다.

**참조와 설명 가운데 무엇을 쓸까.** 참조는 여러 문장이 같은 내용을 가리킬 수 있고, 지시어(`이렇게`, `이것을`)가 문장 안에서 역할을 맡습니다(9장). 설명은 그 문장 하나에 붙는 글입니다. 한 문장에만 해당하는 글은 설명으로, 여러 문장이 함께 가리키는 글은 참조로 적습니다.

## 16.9 나누어 쓰기: 딸린 줄

문장 옆 설명은 짧은 글에 맞습니다. 지시가 여럿이면 한 줄이 오른쪽으로 길어지고, 처음 보는 사람은 그 줄의 어디까지가 문장이고 어디부터가 무엇에 대한 지시인지 찾기 어렵습니다.

```text
신청자가 강의실을 예약한다: 수업 시작 이틀 전까지 신청서를 낸다. 참석 인원이 정원을 넘지 않는지 먼저 확인한다. 신청서에는 수업 이름과 사용 시간을 적는다.
```

0.11부터는 `-`로 시작하는 줄을 문장 아래에 적습니다. 이 책에서는 **딸린 줄**이라고 부릅니다.

```kpl
대상 신청자, 강의실, 담당자
행위 예약하다, 승인하다: 주체, 대상

신청자가 강의실을 예약한다
- 수업 시작 이틀 전까지 신청서를 낸다
- 참석 인원이 정원을 넘지 않는지 먼저 확인한다
- 신청서에는 수업 이름과 사용 시간을 적는다

담당자가 강의실을 승인한다
- 같은 시간에 다른 예약이 없는지 확인한다

본문: 예약 원칙
- 강의실은 수업 목적으로만 쓴다
```

- 딸린 줄은 **가장 가까운 위의** 문장, 조건문, 참조, `본문:` 줄에 딸립니다. 사이에 빈 줄이나 주석이 있어도 됩니다.
- 여러 줄을 이어 적을 수 있습니다. 한 줄에 지시 하나를 적습니다.
- `-` 뒤부터 줄 끝까지가 글이며, 설명과 마찬가지로 `#`과 기호도 글의 일부입니다.
- 문장 옆 설명과 함께 써도 됩니다. 설명은 문장 한 줄의 요약으로, 딸린 줄은 세부 지시로 쓰면 읽기 좋습니다.
- 중간 표현에서는 그 문장의 `items` 항목(글의 목록)이 됩니다.

이렇게 쓰면 무엇이 무엇에 딸렸는지가 위치로 드러납니다. 문장이 제목처럼 맨 앞에 서고, 그 문장에 대한 지시가 바로 아래에 모입니다. 번호로 멀리 떨어진 `참조`를 찾아가지 않아도 됩니다.

딸릴 곳이 없으면 오류입니다. 정의나 조건처럼 글이 딸릴 수 없는 줄 아래에 적어도 같습니다.

```kpl 오류=K200
정의 정원 = 40
- 정의에는 딸리지 않는다
```

```text
예제.kpl(2,3): error K200: '-'로 시작하는 줄은 바로 위의 문장, 참조, 본문에 딸린 글입니다. 위에 그런 줄이 없습니다.
```

정의나 조건에 메모를 남기려면 주석(`#`)을 씁니다. 주석은 컴파일러가 읽지 않는 글이고, 딸린 줄은 명세의 일부로 중간 표현에 남고 17장의 점검을 받는 글입니다.

**왜 `-`인가.** 줄의 처음에 오는 `-`는 다른 문법과 겹치지 않습니다. 뺄셈과 음수의 `-`는 언제나 식 안에 있고, 식으로 시작하는 줄은 없기 때문입니다. 그리고 `-`로 항목을 나열하는 방식은 메모와 문서에서 이미 널리 쓰여 따로 배울 것이 없습니다. 들여쓰기로 딸림을 나타내는 방법도 있지만, 공백의 개수가 뜻을 바꾸면 눈에 보이지 않는 차이로 오류가 생기므로 택하지 않았습니다.

**편집기에서.** 확장은 `.kpl` 파일에서 자동 줄바꿈을 켭니다. 한 줄이 창보다 길어도 오른쪽으로 넘어가지 않고 아래로 접혀 보입니다. 그래도 긴 줄은 나누어 적는 것이 좋습니다. 17장의 `K605`가 80자를 넘는 글을 알려 줍니다.

## 16.10 덜어내지 않은 것

| 그대로인 것 | 이유 |
| --- | --- |
| 주체 없는 문장은 거절 | 누가 하는지 빠진 문장은 읽는 사람마다 다르게 채웁니다(8장). |
| 대상과 행위는 먼저 선언 | 선언이 없으면 오타와 새 이름을 구별할 수 없습니다. |
| 시각과 시간, 위치와 거리의 구분 | 점과 양을 섞는 오류를 막습니다(5장). |
| 단위 없는 수와 단위 있는 양의 구분 | `0`과 `0 원`을 섞게 두면 단위의 뜻이 없어집니다. |
| 미지값의 타입 | 추측하면 오류의 자리를 가리킬 수 없습니다(16.5). |
| 기호 `>=`, `==` | 한 줄씩 명령을 적는 방식에 익숙한 사람에게는 낱말보다 빨리 읽힙니다. |

## 16.11 아직 되지 않는 것

- 미지값에 수를 곱한 제약. `조건 요금 * 2 <= 20만 원`은 `K405`입니다. 7장의 풀이 방법(차이 제약)이 계수가 1인 식만 다루기 때문입니다.
- 단위끼리의 곱과 나눗셈.
- 결과를 `30 분`, `120만 원`처럼 읽기 좋게 보여 주기.
