# 5장. 기준, 시각, 위치

> 이 장에서 배우는 것
> - "언제"(시각)와 "얼마 동안"(시간)이 왜 다른 타입인가
> - 기준(시간축, 위치축)을 선언하고 그 위에 점을 놓는 법
> - 수학의 아핀 공간과 AHAA의 연산 규칙
> - 서로 다른 기준을 섞을 때의 오류

**AHAA에서 이 장의 자리 (잇는다: 언제, 어디서).** 현실의 모든 것은 어느 때 어느 곳에 있습니다. 이 장은 "언제"와 "어디"를 서로 섞이지 않게 적는 바탕입니다.

이 장의 기능은 AHAA 0.2에서 들어왔습니다.

## 5.1 오후 3시 더하기 오후 5시

"오후 3시 + 오후 5시"는 몇 시일까요? 질문 자체가 이상합니다. 그런데 "오후 5시 − 오후 3시"는 2시간이라는 분명한 답이 있고, "오후 3시 + 2시간"도 오후 5시라는 답이 있습니다.

같은 "시간"이라는 말을 쓰지만, 우리는 두 가지 다른 것을 다루고 있습니다.

| | 예 | 질문 |
| --- | --- | --- |
| **시각** | 오후 3시, 실험 시작 후 1초인 순간 | 언제? |
| **시간**(지속 시간) | 2시간, 250밀리초 | 얼마 동안? |

위치와 거리도 마찬가지입니다. "복도 입구에서 3미터 지점"은 위치이고, "3미터"는 거리입니다. 서울역의 위치와 부산역의 위치를 더하는 것은 의미가 없지만, 두 위치의 차이(거리)는 의미가 있습니다.

AHAA는 이 구분을 타입으로 만듭니다.

| 점 (어디/언제) | 양 (얼마나) |
| --- | --- |
| `시각` | `시간` |
| `위치` | `거리` |

## 5.2 이론: 아핀 공간

수학에서 이 구조를 **아핀 공간**(affine space)이라고 합니다. 정의는 다음과 같습니다.

> 아핀 공간은 **점**들의 집합 P와 **벡터**들의 공간 V로 이루어지며, 다음 두 연산이 있다.
> 1. 점에 벡터를 더하면 점이 된다: p + v ∈ P
> 2. 두 점 p, q에 대해 p = q + v인 벡터 v가 **오직 하나** 있다. 이 v를 p − q라고 쓴다.

여기서 **벡터**는 크기(와 방향)를 가진 양이며 서로 더할 수 있습니다. 1차원에서는 부호 있는 수라고 생각하면 됩니다. 이 정의에서 따라 나오는 사실들이 바로 AHAA의 연산 규칙입니다.

| 연산 | 결과 | 정의에서 |
| --- | --- | --- |
| 점 + 양 | 점 | 규칙 1 |
| 점 − 양 | 점 | 규칙 1 (음의 양을 더함) |
| 점 − 점 | 양 | 규칙 2 |
| 양 ± 양 | 양 | 벡터 공간의 성질 |
| 점 + 점 | **정의되지 않음** | 정의에 없음 |

**왜 점끼리는 더할 수 없는가.** 점의 "값"은 원점을 어디에 두느냐에 따라 달라지기 때문입니다. 실험 시작을 원점으로 하면 어떤 순간이 1초이지만, 영상 녹화 시작을 원점으로 하면 같은 순간이 6초일 수 있습니다. 두 순간을 실험 기준으로 더하면 1 + 3 = 4, 영상 기준으로 더하면 6 + 8 = 14입니다. 같은 두 순간인데 답이 다르니, 이 덧셈은 순간들 자체에 대한 의미 있는 정보가 아닙니다. 반면 차이는 어느 기준에서든 3 − 1 = 8 − 6 = 2초로 같습니다. 의미 있는 연산은 **원점을 바꿔도 결과가 변하지 않는 연산**입니다.

이 구조는 생활 곳곳에 있습니다.

- **날짜:** 11월 10일 − 11월 3일 = 7일. 그러나 11월 10일 + 11월 3일은 의미가 없습니다.
- **섭씨 온도:** 섭씨 0도는 물이 어는 온도에 임의로 붙인 원점입니다. 20도와 10도의 차이 10도는 의미가 있지만, 20도는 10도의 "두 배로 따뜻한" 것이 아닙니다. 원점을 절대영도로 옮긴 켈빈 온도에서는 293.15K와 283.15K라서 두 배가 아닙니다.
- **지도의 좌표:** 위도·경도의 원점은 관례로 정한 것입니다.

프로그래밍에서도 같은 구분이 쓰입니다. C++ 표준 라이브러리의 `std::chrono`는 시각(`time_point`)과 지속 시간(`duration`)을 다른 타입으로 두어, 시각끼리 더하면 컴파일 오류가 나게 합니다. AHAA는 여기에 "어느 기준 위의 점인가"까지 타입에 넣습니다.

## 5.3 기준 선언

**기준**(frame)은 원점과 단위를 정한 축입니다.

```text
기준 이름: 시간축
기준 이름: 위치축
```

```aha
기준 실험시계: 시간축
기준 영상시계: 시간축
기준 복도: 위치축
```

`시간축` 기준 위의 점은 `시각`이고, `위치축` 기준 위의 점은 `위치`입니다. 현재 위치축은 1차원(직선)입니다. 2·3차원 좌표계는 앞으로 다룰 확장입니다.

## 5.4 점 만들기: `@`

기준 위의 점은 `기준 @ 양`으로 만듭니다. "기준의 원점에서 이만큼 떨어진 점"이라는 뜻입니다.

```aha
기준 실험시계: 시간축
기준 복도: 위치축

정의 시작: 시각 = 실험시계 @ 1 초
정의 종료: 시각 = 시작 + 250 밀리초
정의 소요: 시간 = 종료 - 시작
정의 입구: 위치 = 복도 @ 0 미터
정의 문: 위치 = 복도 @ 3 미터
정의 폭: 거리 = 문 - 입구

검사 순서 = 종료 > 시작
검사 길이 = 소요 == 250 밀리초 그리고 폭 == 3 미터
```

`@` 뒤에는 기준의 종류에 맞는 양이 와야 합니다. 시간축에는 시간, 위치축에는 거리입니다. `@`는 바로 뒤의 값 하나에만 붙습니다. 식을 놓으려면 괄호로 묶습니다: `실험시계 @ (1 초 + 250 밀리초)`.

```aha 오류=K308
기준 실험시계: 시간축
정의 가: 시각 = 실험시계 @ 1 미터
```

```text
예제.aha(2,17): error K308: 시간축 기준 '실험시계'에는 시간 값을 놓아야 하지만 '거리'가 주어졌습니다.
```

`@` 앞에는 기준 이름이 와야 합니다.

```aha 오류=K308
정의 가: 시각 = 없는기준 @ 1 초
```

## 5.5 연산 규칙

5.2의 표가 그대로 AHAA의 규칙입니다. 점이 들어간 연산만 다시 정리하면 다음과 같습니다.

| 식 | 결과 | 예 |
| --- | --- | --- |
| 시각 + 시간, 시간 + 시각 | 같은 기준의 시각 | `시작 + 250 밀리초` |
| 시각 − 시간 | 같은 기준의 시각 | `시작 - 1 초` |
| 시각 − 시각 | 시간 | `종료 - 시작` |
| 위치 ± 거리, 거리 + 위치 | 같은 기준의 위치 | `입구 + 3 미터` |
| 위치 − 위치 | 거리 | `문 - 입구` |
| 시각끼리, 위치끼리 비교 | 논리 | `종료 > 시작` |
| 시각 + 시각, 위치 + 위치 | `K305` | |
| 시간 − 시각 | `K305` | |
| 점에 부호 `-`, 점의 곱셈 | `K304` | |

### K305: 점끼리 더하기

```aha 오류=K305
기준 실험시계: 시간축
정의 가: 시각 = 실험시계 @ 1 초
정의 나: 시각 = 가 + 가
```

```text
예제.aha(3,14): error K305: '+' 연산으로 '시각(실험시계)'와 '시각(실험시계)'를 계산할 수 없습니다. 기준 위의 점에는 차이(시간·거리)만 더하거나 뺄 수 있습니다.
```

진단 메시지가 `시각(실험시계)`처럼 기준 이름까지 알려 주는 것에 주목하세요.

### K306: 서로 다른 기준

같은 시간축이라도 기준이 다르면 원점이 다릅니다. 두 기준 사이의 관계(원점이 얼마나 떨어져 있는지)를 컴파일러가 모르므로, 다른 기준의 점끼리는 빼거나 비교할 수 없습니다.

```aha 오류=K306
기준 실험시계: 시간축
기준 영상시계: 시간축
정의 시작: 시각 = 실험시계 @ 0 초
정의 녹화: 시각 = 영상시계 @ 5 초
정의 차이: 시간 = 녹화 - 시작
```

```text
예제.aha(5,16): error K306: '-' 연산의 두 값이 서로 다른 기준에 있습니다. 왼쪽은 시각(영상시계), 오른쪽은 시각(실험시계)입니다.
```

실제 실험에서 이것은 흔한 사고입니다. 실험 장비의 시계와 카메라의 시계가 따로 돌아가는데 두 기록을 그대로 비교하면, 몇 초씩 어긋난 결론이 나옵니다. AHAA는 두 시계를 맞추는 정보가 명시되기 전까지 이 비교를 허락하지 않습니다. 기준 사이의 변환을 선언하는 기능은 앞으로의 확장입니다.

### K307: 시각과 지속 시간의 혼동

차원이 같아서(둘 다 시간) 가장 헷갈리기 쉬운 실수입니다. 별도의 진단 코드로 구분해 알려 줍니다.

```aha 오류=K307
기준 실험시계: 시간축
정의 마감: 시각 = 300 밀리초
```

```text
예제.aha(2,4): error K307: '마감'에는 시각 값이 필요하지만 식은 시간입니다. 시각은 '기준 @ 1 초'처럼 시간축 기준 위에 놓아야 합니다.
```

비교에서도 마찬가지입니다. "종료가 300밀리초 이하"라는 말은 "종료 시각이 기준 원점에서 300밀리초 이내"인지 "사건이 300밀리초 이내에 끝났는지"(소요 시간) 모호합니다. AHAA는 어느 쪽인지 밝히게 합니다.

```aha 오류=K307
기준 실험시계: 시간축
정의 종료: 시각 = 실험시계 @ 1 초
검사 제한 = 종료 <= 300 밀리초
```

```text
예제.aha(3,12): error K307: '<=' 연산에 사용할 수 없는 조합입니다. 왼쪽은 시각(실험시계), 오른쪽은 시간입니다. 시각과 지속 시간(위치와 거리)은 비교할 수 없습니다. 점끼리 빼서 차이를 구하세요.
```

뜻에 따라 둘 중 하나로 고칩니다.

```aha
기준 실험시계: 시간축
정의 시작: 시각 = 실험시계 @ 900 밀리초
정의 종료: 시각 = 실험시계 @ 1 초
검사 원점기준 = 종료 <= 실험시계 @ 2 초
검사 소요기준 = 종료 - 시작 <= 300 밀리초
```

### K309: 기준을 값처럼 쓰기

기준은 값이 아니라 값을 놓는 "자"입니다. 기준 이름을 값처럼 쓰면 `K309`입니다.

```aha 오류=K309
기준 실험시계: 시간축
검사 가 = 실험시계 == 실험시계
```

```text
예제.aha(2,8): error K309: '실험시계'는 기준이므로 값으로 쓸 수 없습니다. '실험시계 @ 0 초'처럼 기준 위의 점을 만드세요.
```

## 5.6 왜 이 구분이 명세에 중요한가

프로그램에서 시각과 지속 시간을 같은 숫자 타입으로 다루면, 두 값을 잘못 섞어도 아무도 알려 주지 않습니다. "타임아웃 300밀리초"를 "300밀리초 시각"으로 착각하는 버그는 실제 소프트웨어에서 반복해서 나타납니다. AHAA에서는 이런 착각이 **컴파일 단계에서** 잡힙니다. 사람이 리뷰로 찾아야 했던 오류를 타입이 대신 찾아 주는 것, 이것이 타입 시스템의 가장 큰 가치입니다.

## 정리

- `시각`·`위치`는 기준 위의 **점**, `시간`·`거리`는 **양**입니다.
- 점 − 점 = 양, 점 ± 양 = 점, 점 + 점은 정의되지 않습니다(아핀 공간).
- `기준 이름: 시간축/위치축`으로 기준을 선언하고 `기준 @ 양`으로 점을 만듭니다.
- 다른 기준의 점은 섞을 수 없습니다(`K306`). 시각과 시간을 혼동하면 `K307`입니다.

## 연습 문제

1. 섭씨 온도가 아핀 공간의 예인 이유를 "원점" 개념으로 설명해 보세요.
2. 다음 명세에서 오류를 찾아 고치세요. 의도는 "자극 후 반응까지 500밀리초 이내"입니다.

```aha 오류=K307
기준 실험시계: 시간축
정의 자극: 시각 = 실험시계 @ 1 초
정의 반응: 시각 = 실험시계 @ 1400 밀리초
검사 빠름 = 반응 <= 500 밀리초
```

3. 위치축 `복도`에서 입구가 0미터, 문이 5미터일 때, 입구와 문의 정중앙 위치를 정의해 보세요. (나눗셈이 없다는 점에 주의하세요.)

1. 섭씨 0도는 물이 어는 온도에 붙인 임의의 원점입니다. 원점을 켈빈의 절대영도로 옮기면 온도의 "값"이 바뀌지만, 두 온도의 차이는 그대로입니다. 그래서 온도의 차이는 양(벡터)이고, 온도 자체는 점입니다.
2. `반응`은 시각이고 `500 밀리초`는 시간이므로 비교할 수 없습니다. 의도는 반응과 자극의 차이이므로 `반응 - 자극 <= 500 밀리초`로 고칩니다.
3. 나눗셈 없이 쓰려면 폭의 절반을 직접 적습니다. 정중앙 = 입구 + 2500밀리미터입니다. 컴파일러가 정확히 계산할 수 있도록, 반을 나누는 대신 "두 배 하면 폭이 된다"는 검사로 확인할 수 있습니다.

```aha
기준 실험시계: 시간축
정의 자극: 시각 = 실험시계 @ 1 초
정의 반응: 시각 = 실험시계 @ 1400 밀리초
검사 빠름 = 반응 - 자극 <= 500 밀리초

기준 복도: 위치축
정의 입구: 위치 = 복도 @ 0 미터
정의 문: 위치 = 복도 @ 5 미터
정의 중앙: 위치 = 입구 + 2500 밀리미터
검사 정중앙 = 2 * (중앙 - 입구) == 문 - 입구
```
