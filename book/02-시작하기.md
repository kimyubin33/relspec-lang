# 2장. 시작하기

> 이 장에서 배우는 것
> - 컴파일러를 설치하고 빌드하는 방법
> - 첫 `.aha` 파일을 만들고 `검사`, `컴파일` 명령으로 실행하는 방법
> - 진단 메시지를 읽는 법과 종료 코드
> - 파일 인코딩과 줄 끝에 관한 규칙
> - 낱말과 장면으로 쓴 첫 파일

**AHAA에서 이 장의 자리 (도구).** 이 장에서 설치하는 `aha` 하나로 계산 검사 전체가 돌아갑니다. 적는 법과 잇는 법을 배우기 전에, 글을 검사받는 길부터 엽니다.

## 2.1 준비물

AHAA 컴파일러는 Rust로 작성되어 있습니다. 필요한 것은 두 가지입니다.

1. **Rust 도구 모음**: 공식 설치 도구 `rustup`으로 설치하면 컴파일러(`rustc`)와 빌드 도구(`cargo`)가 함께 설치됩니다. 저장소는 Rust 2024 판(edition)을 사용하므로 최신 안정판을 권장합니다.
2. **저장소**: `relspec-lang` 저장소를 내려받습니다.

```powershell
git clone https://github.com/kimyubin33/relspec-lang.git
cd relspec-lang
```

## 2.2 빌드와 실행

저장소 폴더에서 다음 명령을 실행합니다.

```powershell
cargo build --locked
```

`--locked`는 `Cargo.lock`에 기록된 의존성 버전을 그대로 쓰라는 뜻입니다. 같은 저장소를 받은 사람은 누구나 같은 버전으로 빌드하게 되어, "내 컴퓨터에서는 되는데"라는 문제를 줄입니다.

빌드 없이 바로 실행하려면 `cargo run`을 씁니다. `--` 뒤에 오는 것이 컴파일러에 전달되는 인자입니다.

```powershell
cargo run --locked -- 검사 "./examples/첫파일.aha"
```

배포용으로 최적화한 실행 파일은 `--release`로 빌드합니다. Windows에서는 `target\release\aha.exe`가 만들어집니다.

```powershell
cargo build --release --locked
.\target\release\aha.exe 검사 ".\examples\첫파일.aha"
```

VS Code에서 저장소 폴더를 열면 `.vscode/tasks.json`에 "AHAA Rust 컴파일러 빌드" 작업이 준비되어 있어, 작업 실행 메뉴에서 바로 빌드할 수 있습니다.

## 2.3 첫 파일

아무 편집기에서나 다음 내용을 `첫파일.aha`로 저장합니다. 저장소의 `examples/첫파일.aha`와 같은 내용입니다.

```aha
# 단위를 변환하고 사건의 시간과 거리 조건을 검사합니다.
정의 시작: 시간 = 1 초
정의 종료: 시간 = 시작 + 250 밀리초
정의 소요: 시간 = 종료 - 시작
정의 거리한계: 거리 = 2 미터
정의 이동거리: 거리 = 150 센티미터

검사 시간순서 = 종료 >= 시작
검사 제한충족 = 소요 <= 300 밀리초 그리고 이동거리 <= 거리한계
```

한 줄씩 읽어 보겠습니다.

- `#`부터 줄 끝까지는 **주석**입니다. 컴파일러가 읽지 않습니다.
- `정의 시작: 시간 = 1 초`는 "`시작`이라는 이름의 `시간` 값은 1초다"라는 뜻입니다.
- `정의 종료: 시간 = 시작 + 250 밀리초`에서는 앞서 정의한 `시작`을 이름으로 씁니다. 초와 밀리초를 더해도 컴파일러가 단위를 맞춰 줍니다.
- `검사 시간순서 = 종료 >= 시작`은 "종료가 시작 이상이어야 한다"는 조건입니다. 거짓이면 컴파일이 실패합니다.

## 2.4 두 가지 명령

컴파일러에는 두 가지 명령이 있습니다. 영어 이름도 같은 뜻으로 받습니다.

| 명령 | 영어 이름 | 하는 일 |
| --- | --- | --- |
| `검사` | `check` | 파일을 검사하고 결과를 요약합니다. |
| `컴파일` | `compile` | 파일을 검사한 뒤 내부 표현을 JSON으로 출력합니다. |

`검사`를 실행하면 다음과 같이 요약합니다.

```text
검사 통과 | 정의 5개, 검사 2개
```

선언된 항목의 수를 종류별로 세고, 미지값과 목표가 있으면 그 판정을 줄마다 덧붙입니다(7장).

`컴파일`은 같은 검사를 한 뒤, 모든 값과 식의 구조를 JSON으로 출력합니다. 첫 줄은 언어 버전입니다.

```text
{
  "languageVersion": "0.7",
  "statements": [
    {
      "kind": "정의",
      "name": "시작",
      "type": "시간",
      "value": "1000",
      "unit": "밀리초",
      ...
```

`1 초`가 `"1000"`과 `"밀리초"`로 기록된 것에 주목하세요. 컴파일러는 모든 시간을 밀리초로 바꾸어 정확한 정수로 다룹니다(3장). JSON 출력은 AHAA를 다른 도구와 연결할 때 쓰며, 12장에서 모든 항목을 설명합니다.

도움말은 `--help` 또는 `-h`로 봅니다.

```text
AHAA 0.7
사용법: aha 검사 <파일.aha> | aha 컴파일 <파일.aha>
```

## 2.5 진단 메시지 읽기

명세에 문제가 있으면 컴파일러는 **진단(diagnostic)** 메시지를 내고 멈춥니다. 위 파일에서 `검사 시간순서 = 종료 >= 시작`을 `검사 시간순서 = 종료 < 시작`으로 바꾸어 보겠습니다.

```aha 오류=K401
정의 시작: 시간 = 1 초
정의 종료: 시간 = 시작 + 250 밀리초
검사 시간순서 = 종료 < 시작
```

```text
예제.aha(3,4): error K401: 검사 '시간순서'의 결과가 거짓입니다.
```

메시지는 네 부분으로 되어 있습니다.

| 부분 | 예 | 뜻 |
| --- | --- | --- |
| 파일 | `예제.aha` | 문제가 있는 파일 |
| 위치 | `(3,4)` | 3번째 줄, 4번째 열 |
| 코드 | `K401` | 진단의 종류. 모든 코드는 [부록 A](부록A-진단-코드.md)에 있습니다. |
| 메시지 | `검사 '시간순서'의 결과가 거짓입니다.` | 무엇이 잘못되었고, 가능하면 어떻게 고칠지 |

이 형식은 `파일(줄,열): error 코드: 메시지`로, Visual Studio와 MSBuild가 쓰는 오류 형식과 같습니다. 그래서 편집기가 이 출력을 읽어 오류 위치로 바로 이동할 수 있습니다.

**열 번호에 대하여.** 열은 1부터 세며, 글자 수가 아니라 UTF-16 코드 단위로 셉니다. 한글과 대부분의 문자는 한 글자가 한 단위이므로 글자 수와 같습니다. 일부 이모지처럼 UTF-16에서 두 단위를 차지하는 문자가 앞에 있으면 열 번호가 그만큼 커집니다. Visual Studio와 VS Code가 위치를 세는 방식과 맞추기 위한 선택입니다.

**첫 오류에서 멈춥니다.** 현재 컴파일러는 첫 번째 진단을 보고하고 멈춥니다. 오류를 고친 뒤 다시 실행하면 다음 오류가 있을 경우 그것을 보고합니다.

## 2.6 종료 코드

명령이 끝나면 운영체제에 **종료 코드**를 돌려줍니다. 스크립트나 자동 빌드에서 결과를 판단할 때 씁니다.

| 종료 코드 | 뜻 |
| --- | --- |
| 0 | 검사 통과 |
| 1 | 언어 오류 (진단이 출력됨) |
| 2 | 사용법 오류 또는 파일을 읽을 수 없음 |

## 2.7 파일 형식

- **인코딩:** 파일은 UTF-8로 저장해야 합니다. UTF-8이 아니면 "UTF-8로 저장된 .aha 파일을 입력하세요."라는 메시지와 함께 종료 코드 2로 끝납니다. 파일 맨 앞의 BOM(바이트 순서 표시)은 무시합니다.
- **줄 끝:** Windows(`\r\n`), macOS·Linux(`\n`), 옛 Mac(`\r`) 줄 끝을 모두 같은 것으로 읽습니다.
- **유니코드 정규화:** 한글은 같은 글자를 두 가지 방식으로 저장할 수 있습니다. "가"를 완성형 한 글자(U+AC00)로 저장할 수도 있고, 자모 ㄱ(U+1100)과 ㅏ(U+1161)를 이어서 저장할 수도 있습니다. 눈에는 같아 보이지만 컴퓨터에게는 다른 문자열입니다. 컴파일러는 모든 이름을 **NFC**(정규 합성형)로 바꾸어 비교하므로, 어떤 방식으로 저장된 파일이든 같은 이름은 같은 것으로 인식합니다. macOS의 파일 시스템처럼 자모를 나눠 저장하는 환경에서 만든 파일도 문제없이 읽힙니다.

## 2.8 장면으로 써 보기

2.3의 첫 파일은 값과 검사만 있는 가장 작은 예였습니다. AHAA가 무엇을 하려는 언어인지는 다음 파일에서 더 잘 보입니다. `첫장면.aha`로 저장해 실행해 보세요.

```aha
낱말 컵: 색* 3, 재질, 채움(정도) 2
낱말 식탁: 재질

장면 아침
  식탁: 재질 나무
    컵: 색 흰색, 채움 80%
  빛: 방향 창문, 세기 60%

행위 놓이다: 주체
컵이 놓였다
```

```text
검사 통과 | 정의 0개, 검사 0개, 대상 3개, 행위 1개, 문장 1개, 낱말 2개, 장면 1개
장면 '아침': 낱말 3개, 채움 72% (빈칸 3개: 컵.재질, 빛.색, 빛.때)
```

- `낱말` 줄은 컵과 식탁이 어떤 차원을 가지는지 정합니다.
- `장면` 아래의 들여 쓴 줄은 무엇이 어디 안에 있는지와 차원의 값을 적습니다.
- 마지막 두 줄은 장면의 낱말로 쓴 문장입니다.
- 출력의 둘째 줄이 이 언어의 핵심입니다. 적지 않은 차원 셋을 **빈칸**으로 알려 주고, 얼마나 채웠는지를 수로 보여 줍니다.

각 부분은 3장부터 차례로 배웁니다. 낱말과 장면은 19장에서 다룹니다.

## 정리

- `cargo run --locked -- 검사 파일.aha`로 검사하고, `컴파일`로 JSON을 얻습니다.
- 진단은 `파일(줄,열): error 코드: 메시지` 형식이며, 첫 오류에서 멈춥니다.
- 종료 코드 0은 통과, 1은 언어 오류, 2는 사용법·파일 오류입니다.
- 파일은 UTF-8이며, 이름은 NFC로 정규화해 비교합니다.
