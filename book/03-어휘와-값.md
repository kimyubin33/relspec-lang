# 3장. 어휘와 값

> 이 장에서 배우는 것
> - 파일의 구조: 줄, 주석, 토큰
> - 이름을 짓는 규칙과 예약어
> - 숫자, 참·거짓, 단위가 붙은 값
> - AHAA의 여덟 가지 타입
> - 컴파일러가 값을 정확한 정수로 다루는 이유

**AHAA에서 이 장의 자리 (적는다).** 차원에 들어갈 값의 재료입니다. 수와 단위, 참·거짓, 타입이 있어야 낱말의 차원에 `120 센티미터`, `80%` 같은 값을 채울 수 있습니다(19장).

## 3.1 파일은 줄의 모임이다

AHAA 파일은 **한 줄에 문장 하나**를 적습니다. 문장이 여러 줄에 걸치거나, 한 줄에 문장 두 개를 적을 수는 없습니다.

```aha
정의 가: 정수 = 1

# 빈 줄과 주석만 있는 줄은 건너뜁니다.
정의 나: 정수 = 가 + 1   # 줄 끝 주석도 됩니다.
```

`#`부터 줄 끝까지는 주석입니다. 예외는 9장의 `참조 N:` 줄로, 참조 본문 안의 `#`은 주석이 아니라 본문의 일부입니다.

컴파일러는 각 줄을 **토큰**으로 나눕니다. 토큰은 이름, 숫자, 기호처럼 더 나눌 수 없는 최소 단위입니다. `정의 나: 정수 = 가 + 1`은 `정의`, `나`, `:`, `정수`, `=`, `가`, `+`, `1`의 여덟 토큰입니다. 한 줄에는 토큰을 128개까지 쓸 수 있으며, 넘으면 `K101`입니다. 지나치게 긴 줄은 읽기 어려울 뿐 아니라, 컴파일러가 처리하는 양에 상한을 두어 예측 가능한 시간 안에 끝나도록 하기 위한 제한입니다.

## 3.2 이름

이름은 값, 기준, 대상, 사건 등을 가리킵니다.

- 첫 글자는 **문자**(한글, 로마자, 한자 등 유니코드에서 문자로 분류된 것) 또는 밑줄 `_`입니다.
- 둘째 글자부터는 숫자와 결합 부호도 쓸 수 있습니다.
- 숫자로 시작할 수 없습니다.

```aha
정의 반응시간: 시간 = 200 밀리초
정의 trial_2: 정수 = 2
정의 _임시: 정수 = 0
정의 實驗: 정수 = 1
```

"문자"를 판정할 때는 유니코드 일반 범주(General Category)를 씁니다. 대문자(Lu), 소문자(Ll), 제목 문자(Lt), 수식 문자(Lm), 그 밖의 문자(Lo)가 문자로 인정됩니다. 한글 음절은 "그 밖의 문자(Lo)"에 속합니다. 이렇게 하면 특정 언어에 치우치지 않고 세계의 문자 체계를 일관되게 다룰 수 있습니다.

이름은 대소문자를 구분하고, 2장에서 본 것처럼 NFC로 정규화한 뒤 비교합니다. 같은 이름을 두 번 선언하면 `K301`입니다.

```aha 오류=K301
정의 가: 정수 = 1
정의 가: 정수 = 2
```

```text
예제.aha(2,4): error K301: '가' 이름이 이미 선언되어 있습니다.
```

## 3.3 예약어

다음 낱말은 언어가 쓰므로 이름으로 쓸 수 없습니다.

| 분류 | 예약어 |
| --- | --- |
| 문장 시작 | `정의` `검사` `기준` `대상` `사건` `미지` `조건` `목표` `관측` `행위` `규칙` `참조` |
| 타입 | `정수` `논리` `시간` `거리` `시각` `위치` `대상` `정도` |
| 기준의 종류 | `시간축` `위치축` |
| 논리 | `참` `거짓` `그리고` `또는` `아님` |
| 단위 | `밀리초` `초` `밀리미터` `센티미터` `미터` |

`대상`은 문장 시작(대상 선언)과 타입 양쪽에 쓰입니다.

예약어는 낱말 전체가 같을 때만 예약어입니다. `시작시각`, `거리한계`, `대상물`처럼 예약어를 포함한 긴 이름은 자유롭게 쓸 수 있습니다.

```aha 오류=K200
정의 거리: 정수 = 3
```

```text
예제.aha(1,4): error K200: 선언할 이름을 적으세요.
```

```aha
정의 거리한계: 거리 = 3 미터
```

## 3.4 기호

| 기호 | 쓰임 |
| --- | --- |
| `:` | 이름과 타입 사이, 기준·사건·행위·참조 선언 |
| `=` | 선언에서 이름과 값 사이 |
| `==` `!=` | 같음, 다름 |
| `<` `<=` `>` `>=` | 크기 비교 |
| `+` `-` `*` | 덧셈, 뺄셈(부호), 곱셈 |
| `(` `)` | 식의 묶음, 문장 끝의 참조 목록 |
| `,` | 역할과 참조의 나열 |
| `.` | 사건의 역할 읽기 (`굴림.시작`) |
| `@` | 기준 위의 점 만들기 (`실험시계 @ 1 초`) |
| `?` | 알 수 없는 값 (`미지 반응: 시각 = 실험시계 @ ?`) |
| `%` | 정도 (`70%`) |
| `#` | 주석 |

나눗셈 `/`는 없습니다. 모든 값을 정확한 정수로 다루는데, 나눗셈은 정수가 아닌 결과를 만들기 때문입니다(3.7). 목록에 없는 기호는 `K100`입니다.

```aha 오류=K100
정의 가: 정수 = 3 / 2
```

```text
예제.aha(1,14): error K100: 알 수 없는 기호 '/'입니다.
```

`=`과 `==`를 구분하세요. `=`은 "이 이름은 이 값이다"라는 선언이고, `==`는 "두 값이 같은가"라는 질문입니다. C나 Python과 같은 관례입니다.

## 3.5 리터럴

**리터럴**은 소스에 직접 적은 값입니다.

| 종류 | 예 | 타입 |
| --- | --- | --- |
| 정수 | `0`, `42`, `007` | 정수 |
| 단위가 붙은 수 | `250 밀리초`, `1 초`, `150 센티미터` | 시간, 거리 |
| 정도 | `70%`, `0%`, `100%` | 정도 |
| 참·거짓 | `참`, `거짓` | 논리 |

숫자는 0~9의 십진 숫자만 씁니다. 소수점은 없습니다. 음수는 리터럴이 아니라 부호 연산 `-`로 만듭니다(`-1 초`). 앞의 0은 무시하므로 `007`은 7입니다. 숫자와 단위 사이의 띄어쓰기는 선택입니다. `1초`와 `1 초`는 같습니다.

## 3.6 단위와 기본 단위

| 타입 | 단위 | 기본 단위로 바꾼 값 |
| --- | --- | --- |
| 시간 | `밀리초` | 1 |
| | `초` | 1000 |
| 거리 | `밀리미터` | 1 |
| | `센티미터` | 10 |
| | `미터` | 1000 |

컴파일러는 단위가 붙은 값을 읽는 즉시 **기본 단위**(시간은 밀리초, 거리는 밀리미터)의 정수로 바꿉니다. 그래서 `1 초 + 250 밀리초`는 `1000 + 250 = 1250` 밀리초입니다. 출력과 중간 표현에도 언제나 기본 단위로 기록됩니다.

```aha
정의 합: 시간 = 1 초 + 250 밀리초
검사 확인 = 합 == 1250 밀리초
정의 길이: 거리 = 1 미터 + 5 센티미터
검사 확인2 = 길이 == 1050 밀리미터
```

시간과 거리처럼 **차원**이 다른 값은 더할 수 없습니다.

```aha 오류=K304
정의 가: 시간 = 1 초 + 1 미터
```

```text
예제.aha(1,16): error K304: '+' 연산에 사용할 수 없는 조합입니다. 왼쪽은 시간, 오른쪽은 거리입니다.
```

> **이론: 차원 분석.** 물리학에서는 길이(L), 시간(T), 질량(M)처럼 서로 다른 **차원**의 양을 더하거나 비교할 수 없다는 원칙을 씁니다. 1초와 1미터를 더한 값에는 물리적 의미가 없습니다. 이것을 확인하는 방법을 **차원 분석**이라고 하며, 계산식이 맞는지 빠르게 점검하는 도구로 쓰입니다. AHAA는 차원을 타입으로 만들어, 차원 분석을 컴파일러가 자동으로 하게 합니다. 이런 오류가 실제 사고로 이어진 유명한 예가 1999년 NASA의 화성 기후 궤도선(Mars Climate Orbiter)입니다. 한 팀은 파운드힘·초 단위로, 다른 팀은 뉴턴·초 단위로 값을 주고받은 것이 원인으로 밝혀졌고, 궤도선은 화성 대기에 너무 깊이 들어가 소실되었습니다.

## 3.7 정확한 정수

AHAA는 모든 수를 **임의 정밀도 정수**로 다룹니다. 일반적인 프로그래밍 언어의 정수는 64비트 등 정해진 크기가 있어서, 너무 큰 수를 계산하면 넘침(overflow)이 일어납니다. AHAA의 정수에는 그런 상한이 없습니다.

```aha
정의 큰수: 정수 = 123456789012345678901234567890 * 1000000000
검사 자릿수 = 큰수 > 100000000000000000000000000000000000000
```

`큰수`는 `123456789012345678901234567890000000000`으로 정확히 계산됩니다.

**소수점 수(부동소수점)를 쓰지 않는 이유.** 많은 언어가 소수를 2진 부동소수점으로 저장하는데, 이 방식은 0.1 같은 수를 정확히 나타내지 못합니다. 그래서 0.1 + 0.2가 0.30000000000000004가 되는 일이 생깁니다. 계산 결과가 "거의 같다"는 것으로 충분한 계산기라면 괜찮지만, AHAA는 "보장된다"와 "보장되지 않는다"를 판정하는 언어입니다. 경계값에서 오차가 생기면 판정이 뒤집힐 수 있습니다. 그래서 모든 값을 기본 단위의 정수로 바꾸어, 덧셈·뺄셈·곱셈·비교가 언제나 정확하게 하는 방식을 택했습니다.

이 선택의 대가로 1밀리초보다 짧은 시간, 1밀리미터보다 짧은 거리는 표현할 수 없습니다. 더 작은 단위가 필요해지면 기본 단위를 더 작게 바꾸는 방식으로 확장할 수 있습니다.

## 3.8 여덟 가지 타입

| 타입 | 뜻 | 값의 예 | 자세히 |
| --- | --- | --- | --- |
| `정수` | 단위 없는 정수 | `3`, `-12` | 4장 |
| `논리` | 참 또는 거짓 | `참` | 4장 |
| `시간` | 지속 시간(길이) | `250 밀리초` | 4장, 5장 |
| `거리` | 길이 | `150 센티미터` | 4장, 5장 |
| `시각` | 시간축 기준 위의 한 점 | `실험시계 @ 1 초` | 5장 |
| `위치` | 위치축 기준 위의 한 점 | `복도 @ 3 미터` | 5장 |
| `대상` | 사건에 참여하는 이름 있는 것 | `유빈` | 6장 |
| `정도` | 참인 정도 0~100% | `70%` | 10장 |

`시간`과 `시각`의 차이가 이 언어에서 가장 중요한 구분 가운데 하나입니다. `시간`은 "얼마 동안"(250밀리초 동안)이고, `시각`은 "언제"(실험 시작 후 1초인 순간)입니다. 5장에서 이 구분이 왜 필요한지 수학적으로 설명합니다.

## 정리

- 한 줄에 문장 하나, `#`은 주석, 한 줄의 토큰은 128개까지입니다.
- 이름은 문자나 `_`로 시작하고, 예약어 낱말 전체와 같을 수 없습니다.
- 단위가 붙은 값은 기본 단위(밀리초, 밀리미터)의 정수로 바뀝니다.
- 모든 수는 상한 없는 정확한 정수입니다. 나눗셈과 소수는 없습니다.

## 연습 문제

1. `정의 1등: 정수 = 1`은 왜 오류일까요? 어떻게 고치면 될까요?
2. 다음 검사가 통과하도록 빈칸에 알맞은 수를 넣으세요: `검사 같음 = 3 미터 + 20 센티미터 == ___ 밀리미터`
3. 0.1 + 0.2 문제를 AHAA에서는 어떻게 피할 수 있을까요? 0.1초와 0.2초를 더하는 명세를 써 보세요.

<details>
<summary>풀이</summary>

1. 이름은 숫자로 시작할 수 없습니다. `일등`이나 `등수1`처럼 문자로 시작하게 바꿉니다.
2. 3미터는 3000밀리미터, 20센티미터는 200밀리미터이므로 3200입니다.
3. 0.1초는 100밀리초이므로 정수로 정확히 쓸 수 있습니다.

```aha
정의 합: 시간 = 100 밀리초 + 200 밀리초
검사 정확 = 합 == 300 밀리초
검사 같음 = 3 미터 + 20 센티미터 == 3200 밀리미터
```
