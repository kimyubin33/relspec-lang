# 부록 C. 컴파일러의 구조

RelSpec 컴파일러의 소스를 읽거나 고치려는 사람을 위한 안내입니다. RelSpec 0.10 기준이며, 소스는 저장소의 `src/` 폴더에 있습니다.

## C.1 처리 과정

컴파일러는 소스를 다음 순서로 처리합니다.

```text
소스 글자
  │  어휘 분석 (syntax.rs: scan)        K1xx
  ▼
토큰 목록
  │  구문 분석 (parser.rs: parse)       K2xx
  ▼
문장 목록 (구문 나무)
  │  의미 분석과 평가 (lib.rs: compile)  K3xx, K4xx
  │    ├─ 한국어 문장 (sentence.rs)      K5xx
  │    └─ 차이 제약 (solver.rs)
  ▼
목표 판정, 미지값 범위
  │  본문 점검 (prose.rs)                K6xx (경고)
  ▼
중간 표현 (CompiledProgram) ──▶ 요약 출력 또는 JSON (main.rs, report.rs)
                            └─▶ 편집기 (lsp.rs)
```

1. **어휘 분석**은 글자를 토큰으로 나눕니다. 줄 끝을 통일하고, 이름을 NFC로 정규화하며, 예약어를 구분합니다.
2. **구문 분석**은 토큰을 문장으로 묶고, 식은 우선순위 오르기 방법으로 나무를 만듭니다(4장).
3. **의미 분석과 평가**는 문장을 위에서 아래로 하나씩 처리합니다. 이름을 등록하고, 타입을 확인하고, 값을 계산하고, 조건을 차이 제약으로 바꿔 더합니다.
4. 모든 문장을 처리한 뒤 **목표와 미지값이 든 검사**를 판정하고(7장), 인용한 참조가 정의되었는지 확인하고(9장), 각 미지값의 범위를 구합니다.
5. 설명·참조·`본문:` 줄의 글에서 선언한 이름을 찾고 알림을 만듭니다(17장). 선언이 모두 끝난 뒤에 하므로 뒤에서 선언한 이름도 알아봅니다.
6. 결과를 **중간 표현**으로 모아 돌려줍니다(12장).

## C.3 핵심 자료 구조

**Value(값).** 모든 값은 다음 정보를 가집니다.

| 필드 | 뜻 |
| --- | --- |
| `kind` | 타입 (정수, 시간, 시각, ...) |
| `frame` | 시각·위치라면 어느 기준인지 |
| `number` | 기본 단위의 정수 |
| `label` | 대상이라면 그 이름 |
| `terms` | 미지값의 계수. 값 = number + Σ 계수 × 미지값 |
| `scale` | 정도의 소수 자리 k. 정도 = number ÷ 100ᵏ 퍼센트 (13장) |
| `worlds` | 규칙의 방식에 따라 값이 갈라졌을 때, 방식의 조합(세계)마다의 값 (13장) |

`terms`가 비어 있으면 확정된 값이고, 비어 있지 않으면 미지값이 든 **기호 값**입니다. 덧셈·뺄셈·정수배는 `terms`에도 그대로 적용되므로, `(가 + 200) − 가`처럼 미지값이 지워지는 계산이 정확히 됩니다(11장).

**절(Clause)과 사실(Fact).** 문장 처리는 절 단위입니다(`bind_clause`). 사실을 말하는 문장, 조건문의 전제, 조건문의 결론이 같은 함수로 읽히고 같은 검사를 받습니다. 절은 "행위와 역할들"인 모양(`Pattern`)을 남깁니다. 문장과 조건문의 결론은 모양에 정도를 붙인 **사실**로 `Scope`에 쌓이고, 조건문의 전제는 자기 모양에 해당하는 사실을 찾습니다(`satisfies`). 앞선 조건문들의 전제 모양도 기록해 두었다가, 새 사실이 거기에 해당하면 `K552`를 냅니다(14장).

**세계(World).** 방식을 정하지 않은 규칙이 있으면 값은 여러 세계로 갈라집니다. 세계 하나는 "규칙 번호 → 고른 방식"의 표와 그때의 값입니다. 두 값을 연산할 때는 같은 규칙에 같은 방식을 고른 세계끼리만 짝짓고(`lift2`), 값에 영향을 주지 않는 규칙의 방식을 세계에서 빼고, 모든 세계의 값이 같으면 다시 하나의 값으로 합칩니다(`collapse`). 이 두 함수 덕분에 식 평가 코드는 세계를 의식하지 않고 값 하나를 다루듯 쓸 수 있습니다(13장).

**Closure(폐포).** `solver.rs`의 구조체로, 꼭짓점 사이의 최단 거리 표 D를 가집니다. 꼭짓점 0은 원점이고, 미지값을 선언할 때마다 꼭짓점이 하나씩 늘어납니다. `add(from, to, w)`는 "to − from ≤ w"를 더하며, 모순이면 앞선 제약이 정한 반대쪽 상한을 돌려주어 진단 메시지에 씁니다(7장).

**Scope(이름표).** 값, 기준, 사건, 미지값 정보, 폐포를 함께 가집니다. 문장을 하나 처리할 때마다 갱신됩니다.

## C.4 설계 원칙

- **안전한 Rust만 씁니다.** `Cargo.toml`에 `unsafe_code = "forbid"`를 두어, 컴파일러와 시험 코드 어디에도 `unsafe` 블록을 쓸 수 없게 했습니다.
- **정확한 정수만 씁니다.** 부동소수점을 쓰지 않습니다(3장).
- **첫 오류에서 멈춥니다.** 모든 오류는 `Result`의 오류로 전달되어 곧바로 돌아갑니다. 앞의 오류 때문에 생기는 연쇄 오류를 보여 주지 않습니다. 경고(K6xx)는 오류가 아니므로 중간 표현의 `warnings`에 모두 담습니다.
- **의존성은 최소로 둡니다.** 외부 라이브러리는 유니코드 정규화(`icu_normalizer`), 유니코드 문자 분류(`icu_properties`), JSON 출력(`serde`, `serde_json`)뿐입니다. 받침 계산과 활용형 대응은 한국어 처리 라이브러리 없이 직접 구현합니다(8장).

`tests/book.rs`는 이 책의 코드 블록을 읽어 실제로 컴파일합니다. 블록의 정보 문자열로 기대 결과를 적습니다.

| 정보 문자열 | 뜻 |
| --- | --- |
| `kpl` | 이 블록만으로 컴파일되어야 함 |
| `kpl 오류=K504` | 이 블록만으로 컴파일하면 `K504`가 나와야 함 |
| `kpl 이어서` | 앞 블록에 이어 붙여 컴파일되어야 함 |
| `kpl 이어서 오류=K504` | 앞 블록에 이어 붙이면 `K504`가 나와야 함 |
| `kpl 경고=K601,K602` | 컴파일되고, 본문 점검의 알림이 순서대로 정확히 이것들이어야 함. `경고=`만 적으면 알림이 없어야 함 |

모든 시험은 다음 명령으로 실행합니다.

```powershell
cargo test --locked
```

## C.6 새 기능을 넣는 순서

이 저장소에서 기능을 더할 때는 대체로 다음 순서를 따릅니다.

1. `syntax.rs`에 필요한 토큰과 예약어를 더합니다.
2. `parser.rs`에 문장이나 식의 구문을 더합니다.
3. `lib.rs`(필요하면 별도 모듈)에 의미와 진단을 구현합니다.
4. 중간 표현에 새 항목을 더하되, 비어 있으면 출력하지 않게 해 하위 호환성을 지킵니다.
5. `tests/`에 통과 예제와 진단 예제를 더하고, `examples/`에 실행 예제를 둡니다.
6. `README.md`, `DEVELOPMENT.md`, 그리고 이 책을 갱신합니다.
