# 4장. 정의, 검사, 식

> 이 장에서 배우는 것
> - `정의`와 `검사`의 문법과 뜻
> - 연산자와 우선순위, 식이 나무 구조로 읽히는 원리
> - 타입 규칙: 어떤 값끼리 어떤 연산을 할 수 있는가
> - 선언 순서와 이름 참조

**AHAA에서 이 장의 자리 (적는다).** 값에 이름을 붙이고 식으로 잇는 법입니다. 장면에서 타입이 있는 차원의 값은 이 장의 식으로 읽히고, 이 장의 타입 규칙으로 확인됩니다.

## 4.1 정의

`정의`는 이름 있는 값을 선언합니다.

```text
정의 이름: 타입 = 식
```

```aha
정의 시작: 시간 = 1 초
정의 횟수: 정수 = 3
정의 완료: 논리 = 참
```

타입은 반드시 적습니다. 식의 타입이 적은 타입과 다르면 `K303`입니다.

```aha 오류=K303
정의 가: 시간 = 3
```

```text
예제.aha(1,4): error K303: '가'에는 시간 타입이 필요하지만 식은 정수 타입입니다.
```

`3`은 단위 없는 정수이므로 `시간`이 될 수 없습니다. `3 초`나 `3 밀리초`처럼 단위를 붙여야 합니다. 이 규칙 덕분에 "3이 초인지 밀리초인지" 헷갈리는 일이 생기지 않습니다.

**타입을 꼭 적는 이유.** 컴파일러는 식만 보고도 타입을 알 수 있습니다. 그런데도 적게 하는 것은 타입 선언이 **의도의 기록**이기 때문입니다. 사용자가 "이것은 시간이다"라고 적었는데 식이 정수를 만든다면, 둘 중 하나가 틀린 것이고 컴파일러는 그 불일치를 잡습니다. 명세 언어에서는 중복된 정보가 오류를 찾는 장치가 됩니다.

### 선언 순서

이름은 **선언한 줄보다 뒤에서만** 쓸 수 있습니다.

```aha 오류=K302
정의 나: 정수 = 가 + 1
정의 가: 정수 = 1
```

```text
예제.aha(1,12): error K302: '가'를 사용하기 전에 '정의'로 선언하세요.
```

이 규칙은 순환 정의를 원천적으로 막습니다. `가 = 나 + 1`과 `나 = 가 + 1`을 함께 쓰면 어느 쪽도 값을 정할 수 없는데, 위에서 아래로만 참조할 수 있으면 이런 순환이 생길 수 없습니다. 글을 위에서 아래로 읽듯 명세도 위에서 아래로 읽힌다는 점에서도 자연스럽습니다.

예외가 하나 있습니다. 9장의 참조 본문(`참조 N: ...`)은 각주처럼 파일 어디에 적어도 됩니다.

## 4.2 검사

`검사`는 반드시 참이어야 하는 조건을 선언합니다.

```text
검사 이름 = 논리식
```

```aha
정의 시작: 시간 = 1 초
정의 종료: 시간 = 시작 + 250 밀리초
검사 시간순서 = 종료 >= 시작
검사 소요제한 = 종료 - 시작 <= 300 밀리초
```

`검사`에는 타입을 적지 않습니다. 언제나 `논리`이기 때문입니다. 결과가 거짓이면 `K401`로 컴파일을 멈춥니다. 식이 논리가 아니면 `K303`입니다.

```aha 오류=K303
검사 가 = 1 + 2
```

```text
예제.aha(1,4): error K303: '가'에는 논리 타입이 필요하지만 식은 정수 타입입니다.
```

검사에도 이름을 붙이는 이유는 실패했을 때 무엇이 실패했는지 알려 주기 위해서입니다. "47번째 조건이 거짓"보다 "검사 '소요제한'이 거짓"이 훨씬 빨리 이해됩니다. 검사 이름도 다른 이름과 같은 공간을 쓰므로 정의와 이름이 겹치면 안 됩니다.

미지값이 들어간 검사는 의미가 조금 달라집니다. "모든 가능한 경우에 참이어야 한다"가 됩니다(7장).

## 4.3 연산자와 우선순위

| 우선순위 | 연산자 | 뜻 |
| --- | --- | --- |
| 1 (가장 강함) | `( )` | 묶음 |
| 2 | `-`(부호), `아님` | 단항 연산 |
| 3 | `*` | 곱셈 |
| 4 | `+`, `-` | 덧셈, 뺄셈 |
| 5 | `<`, `<=`, `>`, `>=` | 크기 비교 |
| 6 | `==`, `!=` | 같음, 다름 |
| 7 | `그리고` | 논리곱 |
| 8 (가장 약함) | `또는` | 논리합 |

같은 우선순위의 연산자는 왼쪽부터 묶습니다(왼쪽 결합). `1 - 2 - 3`은 `(1 - 2) - 3 = -4`입니다.

우선순위는 수학과 대부분의 프로그래밍 언어의 관례를 따릅니다. 곱셈이 덧셈보다 먼저이고, 비교가 산술 다음이며, `그리고`가 `또는`보다 먼저입니다. 그래서 `참 또는 거짓 그리고 거짓`은 `참 또는 (거짓 그리고 거짓)`으로 읽혀 참이 됩니다.

```aha
검사 곱셈먼저 = 1 + 2 * 3 == 7
검사 괄호 = (1 + 2) * 3 == 9
검사 그리고먼저 = 참 또는 거짓 그리고 거짓
검사 이중부정 = 아님 아님 참
```

### 이론: 식은 나무다

컴파일러는 `1 + 2 * 3`을 글자 순서대로 계산하지 않습니다. 먼저 식의 구조를 **나무(tree)**로 만듭니다.

```text
      +
     / \
    1   *
       / \
      2   3
```

이 나무를 **구문 나무**(syntax tree)라고 하고, 글을 나무로 바꾸는 과정을 **구문 분석**(parsing)이라고 합니다. 나무가 만들어지면 아래에서 위로 계산합니다. 먼저 `2 * 3 = 6`, 그다음 `1 + 6 = 7`입니다. 우선순위는 "어떤 연산이 나무의 아래쪽(먼저 계산)에 오는가"를 정하는 규칙입니다.

AHAA 컴파일러는 **우선순위 오르기**(precedence climbing)라는 방법으로 이 나무를 만듭니다. 식을 읽다가 연산자를 만나면, 그 연산자보다 강한 연산자들을 먼저 오른쪽 부분 나무로 묶고 돌아오는 방식입니다. 연산자 하나에 우선순위 숫자 하나만 있으면 되므로 표를 고치는 것만으로 새 연산자를 넣을 수 있습니다. 같은 계열의 방법으로 Vaughan Pratt가 1973년에 발표한 **Pratt 구문 분석**이 있으며, 많은 현대 컴파일러가 식을 이 계열의 방법으로 읽습니다.

`컴파일` 명령의 JSON 출력에는 이 나무가 그대로 기록됩니다(12장).

## 4.4 타입 규칙

연산마다 받을 수 있는 타입이 정해져 있습니다. 맞지 않는 조합은 `K304`입니다.

### 산술

| 연산 | 가능한 조합 | 결과 |
| --- | --- | --- |
| `+`, `-` | 정수와 정수 | 정수 |
| | 시간과 시간 | 시간 |
| | 거리와 거리 | 거리 |
| `*` | 정수와 정수 | 정수 |
| | 정수와 시간 (어느 쪽이든) | 시간 |
| | 정수와 거리 (어느 쪽이든) | 거리 |
| 부호 `-` | 정수, 시간, 거리 | 같은 타입 |

곱셈은 **적어도 한쪽이 정수**여야 합니다. `2 * 3 초`는 6초이지만, `2 초 * 3 초`는 "제곱초"라는 새 차원이 되므로 지원하지 않습니다.

```aha 오류=K304
정의 가: 시간 = 2 초 * 3 초
```

```text
예제.aha(1,16): error K304: '*' 연산에 사용할 수 없는 조합입니다. 왼쪽은 시간, 오른쪽은 시간입니다.
```

### 비교

| 연산 | 가능한 조합 | 결과 |
| --- | --- | --- |
| `<`, `<=`, `>`, `>=` | 같은 타입의 정수, 시간, 거리 (5장의 시각·위치, 10장의 정도도 가능) | 논리 |
| `==`, `!=` | 같은 타입이면 무엇이든 | 논리 |

비교는 **같은 타입끼리**만 됩니다. 단위는 달라도 됩니다. `1 초 == 1000 밀리초`는 참입니다. 둘 다 기본 단위로 1000이기 때문입니다.

**연쇄 비교는 없습니다.** 수학에서 쓰는 `1 < 2 < 3`은 AHAA에서 `(1 < 2) < 3`, 즉 `참 < 3`이 되어 타입 오류입니다. 범위를 쓰려면 `그리고`로 나눕니다.

```aha 오류=K304
정의 가: 논리 = 1 < 2 < 3
```

```aha
정의 값: 정수 = 2
검사 범위 = 1 < 값 그리고 값 < 3
```

### 논리

| 연산 | 가능한 조합 | 결과 |
| --- | --- | --- |
| `그리고`, `또는` | 논리와 논리 | 논리 |
| `아님` | 논리 | 논리 |

10장에서 `정도` 타입이 들어오면 이 연산들이 퍼지 논리로 확장됩니다.

**양쪽을 모두 검사합니다.** 많은 프로그래밍 언어는 `거짓 그리고 X`에서 왼쪽이 거짓이면 X를 보지 않습니다(단락 평가). AHAA는 X를 계산할 필요가 없더라도 X의 타입은 반드시 검사합니다. 명세 언어에서 "실행되지 않는 부분의 오류"를 숨기면 나중에 값이 바뀌었을 때 갑자기 드러나기 때문입니다.

```aha 오류=K304
검사 가 = 거짓 그리고 (1 초 > 1 미터)
```

## 4.5 모든 값은 컴파일할 때 정해진다

지금까지의 식은 모든 값이 확정되어 있습니다. 그래서 컴파일러는 식을 컴파일하는 순간 값을 계산해 둡니다. 이를 **상수 접기**(constant folding)라고 합니다. AHAA 프로그램은 실행 단계가 따로 없고, 컴파일이 곧 검사입니다.

값이 정해지지 않은 경우(미지값)는 7장에서 다룹니다. 그때는 값 하나 대신 가능한 범위를 계산합니다.

## 4.6 자주 하는 실수

| 실수 | 진단 |
| --- | --- |
| 한 줄에 문장 두 개 | `K200`: 한 줄에는 문장 하나를 적으세요. |
| `정의 가 정수 = 1` (콜론 빠짐) | `K200`: 이름 뒤에 ':'와 타입을 적으세요. |
| `검사 가: 논리 = 참` (검사에 타입) | `K200`: 식 앞에 '='를 적으세요. |
| 비교에 `=` 사용 | `K200`: ... 비교에는 '=='를 사용합니다. |

```aha 오류=K200
정의 가: 정수 = 1 정의 나: 정수 = 2
```

```text
예제.aha(1,14): error K200: 한 줄에는 문장 하나를 적으세요. 비교에는 '=='를 사용합니다.
```

## 정리

- `정의 이름: 타입 = 식`은 값을, `검사 이름 = 논리식`은 참이어야 할 조건을 선언합니다.
- 이름은 선언한 뒤에만 쓸 수 있어 순환 정의가 생기지 않습니다.
- 식은 우선순위에 따라 나무로 읽히고, 아래에서 위로 계산됩니다.
- 연산은 타입이 맞아야 하며, 곱셈은 한쪽이 정수여야 하고, 비교는 같은 타입끼리만 됩니다.

## 연습 문제

1. `2 * 3 + 4 * 5`의 구문 나무를 그려 보세요.
2. 다음 중 오류인 것과 그 진단 코드를 고르세요.
   (가) `정의 가: 시간 = 3 * 2 초`
   (나) `정의 나: 거리 = 2 미터 * 2 미터`
   (다) `검사 다 = 1 초 == 1000 밀리초`
   (라) `정의 라: 정수 = -(-3)`
3. 값이 0 이상 10 이하인지 확인하는 검사를 써 보세요.

<details>
<summary>풀이</summary>

1. `+`가 뿌리이고, 왼쪽 가지는 `2 * 3`, 오른쪽 가지는 `4 * 5`입니다. 결과는 26입니다.
2. (나)만 오류이며 `K304`입니다. 거리끼리는 곱할 수 없습니다. (가)는 6초, (다)는 참, (라)는 3입니다.
3. 아래처럼 `그리고`로 두 비교를 묶습니다.

```aha
정의 가: 시간 = 3 * 2 초
검사 다 = 1 초 == 1000 밀리초
정의 라: 정수 = -(-3)
검사 라확인 = 라 == 3
정의 값: 정수 = 7
검사 범위 = 0 <= 값 그리고 값 <= 10
검사 식 = 2 * 3 + 4 * 5 == 26
```

</details>
