# RelSpec

RelSpec(*Relation Specification*)은 시간, 공간, 사건의 관계를 명세하고 그 조건을 수학적으로 검사하는 언어입니다. 한글 문법부터 개발하며, 영어 문법도 같은 타입과 검사 규칙을 사용하도록 설계합니다.

현재는 Rust로 구현한 0.12 컴파일러이며, VS Code에서 코드처럼 쓸 수 있는 [확장](editors/vscode/README.md)과 언어 서버가 들어 있습니다. 언어의 목표와 이론적 근거는 [설계 방향](VISION.md)에 정리했습니다. 기초부터 이론까지 배우려면 [RelSpec 언어 교재](book/README.md)를 읽으세요. 명령 실행 파일 이름은 `kpl`, 소스 확장자는 `.kpl`입니다. 개발 방식과 어디까지 개발되었는지, 앞으로의 계획은 [개발 현황](PROGRESS.md)에, 버전별 세부 구현 상태는 [개발 방향과 구현 상태](DEVELOPMENT.md)에 정리했습니다.

## 실행

Rust와 Cargo가 설치된 환경에서 저장소 폴더를 열고 실행합니다.

```powershell
cargo run --locked -- 검사 "./examples/첫파일.kpl"
cargo run --locked -- 컴파일 "./examples/첫파일.kpl"
cargo run --locked -- 검사 "./examples/사건관계.kpl"
cargo run --locked -- 검사 "./examples/반응마감.kpl"
cargo run --locked -- 검사 "./examples/문장과정도.kpl"
cargo run --locked -- 검사 "./examples/반응시제.kpl"
cargo run --locked -- 검사 "./examples/정도전파.kpl"
cargo run --locked -- 검사 "./examples/조건문.kpl"
cargo test --locked
```

`검사`는 정의와 검사 조건의 개수를 요약합니다. `컴파일`은 검사에 통과한 프로그램의 값, 타입, 단위, 식의 연결을 JSON으로 출력합니다. 언어 오류의 종료 코드는 1이며, 파일이나 명령 사용 오류는 2입니다.

Windows용 실행 파일은 `cargo build --release --locked`로 빌드한 뒤 아래와 같이 실행할 수 있습니다.

```powershell
.\target\release\kpl.exe 검사 ".\examples\첫파일.kpl"
```

## 현재 문법

### 값과 검사

```text
정의 시작: 시간 = 1 초
정의 종료: 시간 = 시작 + 250 밀리초
검사 시간순서 = 종료 >= 시작
검사 소요제한 = 종료 - 시작 <= 300 밀리초
```

- `정의`는 타입이 있는 고정값을 선언합니다. 선언한 줄 뒤에서 이름으로 참조할 수 있습니다.
- `검사`는 참이어야 하는 논리식을 선언합니다. 거짓이면 컴파일을 중단하고 검사 이름과 위치를 표시합니다.
- 타입은 `정수`, `논리`, `시간`, `거리`, `시각`, `위치`, `대상`, `정도`입니다. 정도는 곱셈 결과를 위해 `16.5%`처럼 정확한 소수를 가질 수 있습니다. 시간·시각은 밀리초, 거리·위치는 밀리미터로 정확히 환산합니다.
- 연산은 괄호, 단항 `-`와 `아님`, `*`, `+`와 `-`, 크기 비교, `==`와 `!=`, `그리고`, `또는` 순으로 우선합니다. 곱셈은 적어도 한쪽이 정수여야 합니다.
- UTF-8 파일에 한 줄당 문장 하나를 적습니다. 빈 줄과 `#` 주석을 허용하며, 한 줄은 토큰 128개까지 지원합니다.

### 기준, 시각과 위치

`시간`과 `거리`는 **양**(지속 시간, 길이)이고, `시각`과 `위치`는 **기준 위의 점**입니다. 점은 `기준 @ 값`으로 만듭니다.

```text
기준 실험시계: 시간축
기준 복도: 위치축
정의 던짐: 시각 = 실험시계 @ 1 초
정의 도착점: 위치 = 복도 @ 3 미터
```

| 계산 | 결과 |
| --- | --- |
| 시각 ± 시간, 시간 + 시각 | 같은 기준의 시각 |
| 시각 − 시각 (같은 기준) | 시간 |
| 위치 ± 거리, 거리 + 위치 | 같은 기준의 위치 |
| 위치 − 위치 (같은 기준) | 거리 |
| 시각 + 시각, 위치 + 위치 | 오류 `K305` |
| 서로 다른 기준의 점끼리 계산·비교 | 오류 `K306` |
| 시각 자리에 시간을 쓰거나 시각과 시간을 비교 | 오류 `K307` |

### 대상과 사건

```text
대상 공
대상 유빈
사건 굴림: 주체 = 유빈, 대상 = 공, 시작 = 던짐, 종료 = 던짐 + 1500 밀리초, 출발 = 복도 @ 0 미터, 도착 = 도착점
사건 잡기: 주체 = 유빈, 시작 = 굴림.종료 + 200 밀리초
검사 순서 = 잡기.시작 > 굴림.종료
검사 소요제한 = 굴림.소요 <= 2 초
```

- 역할: `주체`·`대상`·`관측자`(대상), `시작`·`종료`(시각), `출발`·`도착`(위치).
- `시작`은 필수입니다. `종료`를 생략하면 시작과 같은 시각의 순간 사건이 됩니다. `출발`과 `도착`은 함께 적습니다.
- 같은 사건의 시작·종료, 출발·도착은 같은 기준에 있어야 하며, 종료가 시작보다 앞서면 `K402`입니다.
- `사건.역할`로 역할 값을 읽고, `사건.소요`(종료 − 시작)와 `사건.이동`(도착 − 출발)으로 차이를 읽습니다.
- 대상끼리는 `==`, `!=`로 같은지만 비교합니다.

### 미지값, 조건, 목표, 관측

값을 아직 모르는 양은 `미지`로 선언하고, `조건`으로 범위를 좁힌 뒤 `목표`가 **보장**·**가능**·**불가능** 중 무엇인지 판정합니다.

```text
기준 실험시계: 시간축
사건 자극: 시작 = 실험시계 @ 1000 밀리초
미지 반응: 시각 = 실험시계 @ ?
조건 반응은자극뒤 = 반응 >= 자극.시작
조건 지연상한 = 반응 - 자극.시작 <= 200 밀리초
목표 마감준수 = 반응 <= 실험시계 @ 1100 밀리초
```

```text
검사 통과 | 정의 0개, 검사 0개, 기준 1개, 사건 1개, 미지 1개, 조건·관측 2개, 목표 1개
미지 '반응': 1000 밀리초 ~ 1200 밀리초 (실험시계 기준)
목표 '마감준수': 가능 (보장 여부를 확정하려면 관측 필요: 반응)
```

- `미지 이름: 시간 = ?`(정수·시간·거리), `미지 이름: 시각 = 기준 @ ?`(시각·위치)로 선언합니다.
- `조건`은 모든 해가 따라야 하는 가정입니다. 조건끼리 모순이면 뒤에 나온 조건에서 `K404`를 냅니다.
- `목표`는 컴파일을 멈추지 않고 판정만 기록합니다. **보장**은 모든 해에서, **가능**은 일부 해에서 성립하며, **불가능**은 어떤 해에서도 성립하지 않습니다. 가능일 때는 판정을 확정하는 데 필요한 미지값을 표시합니다.
- `관측 반응 = 실험시계 @ 1080 밀리초`는 미지값의 실제 값을 기록합니다. 조건과 충돌하면 `K404`입니다.
- 미지값이 들어간 `검사`는 모든 해에서 **보장**되어야 통과합니다(`K403`).
- 지원하는 제약은 미지값 하나의 상·하한(`가 <= 값`)과 두 미지값의 차이(`가 - 나 <= 값`)이며, `그리고`로 묶을 수 있습니다. `또는`, `!=`, 미지값의 합이나 배수는 `K405`입니다. 정수 밀리초·밀리미터 단위로 판정하므로 `가 < 나`는 `가 - 나 <= -1`과 같습니다.

### 문장, 참조, 정도

키워드로 시작하지 않는 줄은 **문장**입니다. 문장 하나는 사건 하나이며, 낱말 끝의 조사가 역할을 정하고 마지막 낱말이 행위(동사)입니다.

```text
대상 유빈
대상 설계안
대상 컵
행위 설계하다: 주체, 대상
행위 떨어지다: 주체

이렇게 설계를 하다
# → K504: 행위 '설계하다'에는 '주체' 역할이 필요합니다.

유빈이 설계안을 이렇게 설계했다 (참조 1)
떨어짐: 컵이 70% 떨어졌다
정의 공존: 정도 = 떨어짐 그리고 아님 떨어짐   # 30%

참조 1: 모듈을 세 층으로 나누고, 각 층은 바로 아래 층만 참조한다
```

- `행위 기본형: 역할, ...`로 행위와 필수 역할을 선언합니다. 주체는 항상 필수입니다. 역할: 주체, 대상, 상대, 도구, 시작, 종료, 장소, 출발, 도착, 방식.
- 조사: 이/가·은/는 → 주체, 을/를 → 대상, 에게·한테 → 상대, 으로/로 → 도구, 에·부터·까지·에서 → 앞말이 시각이면 시작·종료, 위치면 장소·출발·도착. 받침에 맞지 않는 조사 형태는 `K502`입니다.
- 활용형(했다, 졌다, 왔다, 굴렀다)과 기능동사 구문(설계를 하다)을 기본형과 연결합니다. 그 밖의 불규칙 활용은 `행위 듣다 (들었다): 주체`처럼 적습니다.
- 지시어(이렇게·그렇게·저렇게, 이것·그것·저것)는 문장 끝 `(참조 N)`이 있어야 하며, `참조 N: 본문`은 파일 어디에든 적을 수 있습니다.
- `이름: 문장`으로 이름을 붙이면 그 문장의 **정도**를 식에서 쓸 수 있습니다. 정도를 적지 않으면 100%입니다.
- `정도` 타입은 퍼지 논리를 따릅니다: `그리고` = 최솟값, `또는` = 최댓값, `아님` = 100% − 값. `참`·`거짓`은 100%·0%로 섞어 쓸 수 있습니다.

### 문장 속 미지값과 시제

문장과 `사건`의 시각·위치 역할에는 미지값을 쓸 수 있습니다. 이름 붙은 문장은 정도이면서 사건이기도 해서 `이름.시작`, `이름.소요`처럼 역할을 읽을 수 있습니다.

```text
정의 지금: 시각 = 실험시계 @ 3 초
미지 반응: 시각 = 실험시계 @ ?
눌림: 유빈이 반응에 버튼을 눌렀다
조건 지연상한 = 눌림.시작 - 자극.시작 <= 2500 밀리초
```

```text
미지 '반응': 1000 밀리초 ~ 3000 밀리초 (실험시계 기준)
```

- 종료는 시작보다 앞설 수 없습니다. 값이 확정되어 있으면 바로 확인하고(`K402`), 미지값이 있으면 그 관계를 제약으로 더합니다.
- `지금`을 시각으로 정의하면 동사의 시제가 제약이 됩니다. 과거(했다, 떨어졌다): 사건이 지금까지 끝남. 현재(한다, 먹는다): 지금이 사건 안에 있음. 미래(하겠다): 사건이 지금보다 뒤에 시작함. 기본형(하다)에는 시제가 없습니다. 맞지 않으면 `K530`입니다.
- 위치는 시간과 달리 뒤로도 움직일 수 있으므로 도착이 출발보다 앞서도 됩니다.

### 규칙과 정도의 전파

`규칙 이름: 전제 이면 강도`는 전제의 정도를 결론으로 전파합니다. 결론의 정도는 `이름`으로 식에서 씁니다.

```text
떨어짐: 컵이 70% 떨어졌다
규칙 깨짐: 떨어짐 이면 80%              # 방식을 정하지 않음: 두 방식 모두 계산
규칙 미끄러짐: 젖음 이면 90% 곱으로      # 곱(Larsen)으로만 계산
목표 깨짐심함 = 깨짐 >= 60%
```

```text
규칙 '깨짐': 56%~70% (최소 70%, 곱 56%)
목표 '깨짐심함': 가능 (규칙의 계산 방식에 따라 다름: 깨짐)
```

- `최소로`는 Mamdani 방식 min(전제, 강도), `곱으로`는 Larsen 방식 전제 × 강도입니다. 곱은 `16.5%`처럼 정확한 소수를 만들며, 반올림하지 않습니다.
- 방식을 적지 않으면 두 방식을 모두 계산합니다. 방식을 정하지 않은 규칙마다 세계가 둘로 나뉘고, 규칙이 이어지면 모든 조합을 따집니다(최대 4096가지).
- 목표는 모든 조합에서 충족하면 **보장**, 일부에서만 충족하면 **가능**(판정을 가르는 규칙을 표시), 어느 조합에서도 아니면 **불가능**입니다. `검사`는 모든 조합에서 참이어야 통과합니다(`K540`).
- 두 방식의 결과가 같으면(전제가 100%나 0% 등) 하나로 합쳐집니다.

### 문장으로 쓰는 규칙

`-면`으로 이은 문장은 규칙입니다. `-면` 앞이 전제, 뒤가 결론이고, 결론에 적은 정도가 규칙의 강도입니다.

```text
컵이 70% 떨어졌다
깨짐: 컵이 떨어지면 컵이 80% 깨진다
컵이 깨지면 바닥이 90% 젖는다 곱으로
```

```text
조건문 '깨짐': 56%~70% (최소 70%, 곱 56%)
조건문 3행: 50.4%~63% (곱으로 계산)
```

- 전제는 **앞에 적힌 사실** 가운데 행위가 같고 전제의 역할을 모두 같은 값으로 가진 것을 찾아 그 정도를 씁니다. 사실에 역할이 더 있어도 됩니다. 해당하는 사실이 여럿이면 가장 큰 정도를 씁니다.
- 결론은 새 사실이 되어 다음 조건문의 전제가 됩니다. 같은 결론을 내는 조건문이 여럿이면, 그 결론을 전제로 쓸 때 가장 큰 정도가 쓰입니다.
- 해당하는 사실이 없으면 짐작하지 않고 `K551`입니다. 일어나지 않은 일은 `컵이 0% 떨어졌다`처럼 적습니다.
- 사실은 그것을 쓰는 조건문보다 앞에 있어야 합니다(`K552`). 결론이 자기 전제로 돌아오는 순환도 `K552`입니다.
- 전제의 꼴은 어간 + `-면`(받침이 없거나 ㄹ 받침: 떨어지면, 살면) 또는 `-으면`(그 밖의 받침: 먹으면)입니다. 불규칙 활용은 `행위 듣다 (들었다, 들으면)`처럼 적습니다.
- 강도를 적지 않으면 100%입니다. 계산 방식 `최소로`·`곱으로`는 결론 안이나 뒤에 적으며, 적지 않으면 두 방식을 모두 계산합니다.
- `이름:`을 붙이면 결론의 정도를 식에서 쓰고 `이름.주체`처럼 역할도 읽습니다. 이름이 없으면 `3행`처럼 줄 번호로 부릅니다.

### 짧게 쓰기 (0.9)

위의 문법은 모두 그대로 쓸 수 있고, 같은 뜻을 다음처럼 더 짧게 쓸 수 있습니다.

```text
대상 신청자, 강의실                 # 여러 이름을 한 줄에
행위 예약하다, 승인하다: 주체, 대상   # 필수 역할을 함께 쓰는 행위들
단위 원, 명                         # 새 단위. 단위가 다르면 더하거나 비교할 수 없습니다.

신청자가 강의실을 예약한다: 수업 시작 2일 전까지 신청서를 낸다   # 문장 뒤에 설명

정의 정원 = 40 명                   # 타입은 값에서 정해집니다.
정의 최대요금 = 12만 원              # 만, 억 같은 큰 수 낱말
정의 기본시간 = 2 시간               # 분, 시간, 일, 킬로미터
검사 정원 > 0 명                    # 이름 없는 검사
미지 참석자: 명                      # '= ?' 생략
조건 참석자 >= 1 명
목표 참석자 <= 정원                  # 결과에 식이 그대로 표시됩니다.
```

`examples/쓰기쉽게.kpl`에 전체 예제가 있습니다.

### 연결망 (0.12)

명세에 적힌 것을 점으로, 그 관계를 선으로 옮겨 봅니다.

```powershell
kpl 그래프 examples/조건문.kpl
```

```text
연결망 | 점 16개, 선 23개, 덩어리 1개
examples/조건문.그래프.html
```

만들어진 HTML 파일 하나를 브라우저로 열면 됩니다(다른 파일이나 인터넷이 필요 없습니다). 대상·행위·값·기준이 점이 되고, 문장은 그 점들을 역할로 잇는 점이 됩니다. 정도는 문장의 점 둘레에 호로 그려집니다. 실선은 컴파일러가 확인한 관계이고, 점선은 자유로운 글에 선언한 이름이 나온 자리(언급)입니다.

덩어리가 여럿이면 명세가 서로 이어지지 않은 부분들로 나뉘어 있다는 뜻이며, 무엇이 떨어져 있는지 출력합니다. VS Code에서는 "RelSpec: 연결망 보기" 명령으로 편집기 옆에 엽니다.

### 나누어 쓰기 (0.11)

지시가 여럿이면 문장 옆에 길게 잇지 않고, `-`로 시작하는 줄로 문장 아래에 하나씩 적습니다. 딸린 줄은 가장 가까운 위의 문장·참조·`본문:` 줄에 딸립니다.

```text
신청자가 강의실을 예약한다
- 수업 시작 이틀 전까지 신청서를 낸다
- 참석 인원이 정원을 넘지 않는지 먼저 확인한다

본문: 예약 원칙
- 강의실은 수업 목적으로만 쓴다
```

`examples/나누어쓰기.kpl`에 예제가 있습니다.

### 본문 점검 (0.10)

문장 뒤의 설명, `참조`의 본문, `본문:` 줄은 자유롭게 쓰는 글입니다. 컴파일러는 글 안에서 선언한 이름을 알아보고, 확실하게 말할 수 있는 문제만 알립니다. 알림은 경고이며 컴파일을 막지 않습니다.

```text
단위 원
정의 기본요금 = 3만 원
정의 예약마감 = 2 일
대상 신청자
본문: 신청자는 예약 마감 전에 3만 원을 적절히 낸다
```

| 코드 | 알림 | 예 |
| --- | --- | --- |
| K601 | 정의한 값과 같은 양이 본문에 따로 적혀 있음 | `3만 원` (= 기본요금) |
| K602 | 기준이 정해지지 않은 낱말 | `적절히` |
| K603 | 무엇을 가리키는지 확인할 수 없는 지시어 | `해당`, `그것` |
| K604 | 선언한 이름을 띄어 씀 | `예약 마감` (↔ 예약마감) |
| K605 | 글 한 줄이 80자를 넘음 | 여러 지시를 한 줄에 이어 적은 설명 |

알림이 없다는 것은 위의 항목에 해당하는 곳이 없다는 뜻이지, 글이 한 가지로만 읽힌다는 보장이 아닙니다. 보장이 필요한 내용은 문장과 `조건`·`목표`로 적으세요. `examples/본문점검.kpl`에 예제가 있습니다.

## 편집기에서 쓰기

`kpl lsp`는 Language Server Protocol(LSP)을 따르는 언어 서버입니다. 편집기가 이 명령을 실행해 표준 입출력으로 대화합니다.

| 기능 | 내용 |
| --- | --- |
| 실시간 진단 | 글자를 칠 때마다 컴파일해서 오류를 그 낱말 아래에 표시합니다. |
| 판정 결과 표시 | 목표의 판정, 미지값의 범위, 규칙과 조건문의 정도를 그 줄에 정보로 표시합니다. 불가능한 목표는 경고입니다. |
| 설명 | 낱말에 마우스를 올리면 값, 문장에서 맡은 역할, 행위의 기본형, 판정 결과를 보여 줍니다. |
| 자동 완성 | 선언 낱말, 타입, 단위와 이 파일에서 선언한 이름 |
| 정의로 이동 | 이름(조사가 붙어 있어도 됨), 활용형 → 행위 선언, `(참조 1)` → `참조 1:` |
| 문서 개요 | 선언한 이름과 참조의 목록 |

VS Code용 확장은 `editors/vscode`에 있으며 문법 색칠도 제공합니다. 설치와 실행 방법은 [확장 안내](editors/vscode/README.md)를 보세요.

```powershell
cargo build --release --locked
cd editors/vscode
npm install
```

그다음 VS Code에서 `editors/vscode` 폴더를 열고 `F5`를 누르면 확장이 들어간 창이 뜹니다.

## Rust 안전 정책

`Cargo.toml`에서 `unsafe_code = "forbid"`를 설정했습니다. KPL 패키지의 라이브러리, CLI, 테스트에는 `unsafe` 블록, raw pointer 역참조, `unsafe` 함수 호출, 가변 정적 변수 접근을 사용하지 않습니다. Rust 표준 라이브러리와 외부 의존성의 내부 구현은 별도의 범위입니다.
